# PLAY YOUR LIFE

Мобильное веб-приложение для личного развития с геймификацией.
Основная версия проекта находится в ветке `main` репозитория `vodolivan95/play-your-life`.

- Не реализовывать функции, экраны или дизайн без нового задания пользователя.
- Не подключать базу данных, авторизацию, аналитику или платные сервисы без задания.
- Общаться и вести пользовательскую документацию на русском.
- Перед завершением изменения запускать `npm run check`.
- Использовать npm и сохранять package-lock.json.
- Не коммитить секреты и файлы .env.

## Работа в облаке

- По просьбе пользователя работать с исходниками через GitHub или облачное рабочее окружение.
- Проверять изменения через GitHub Actions: `npm run check` и `npm test`; дождаться результата для соответствующего коммита.
- Не создавать новые локальные копии проекта, распакованные копии или архивы без отдельного запроса пользователя.
- Считать `main` единственным источником актуальной опубликованной версии. Старые ветки и архивы не использовать как основу новых изменений.

## Единый проект Claude и Codex

Claude и Codex работают с одним проектом. Единственный источник актуальной версии — ветка `main` репозитория `vodolivan95/play-your-life`. Перед началом работы помощник получает свежий `origin/main`, а после завершения сохраняет изменения через отдельную ветку и Pull Request. Важные файлы нельзя оставлять только в чатах или артефактах.

- Перед работой: `git fetch origin main`. Незакоммиченные чужие изменения сначала сохранять и разбирать (`git stash` / отдельный коммит), не удалять и не перезаписывать.
- Ветка на задачу от свежего `main`: `claude/<задача>` или `codex/<задача>`.
- После задачи: проверки (`npm run check`, `npm test`, в CI — UI-тесты), коммит всех связанных файлов, push ветки, PR в `main`, зелёные GitHub Actions, слияние (по прямому поручению Ивана помощник может слить свой PR), в отчёте — полный SHA коммита в `main`.
- Без `force push`, без переписывания истории, без удаления чужих изменений.
- Макеты в Claude Artifact / Claude Design — только прототип: итог переносится в репозиторий (код, стили, изображения, шрифты, ресурсы, тесты, документация). Согласованные холсты записываются ссылкой в `AGENTS.md` и `docs/`.
- После изменений обновлять `AGENTS.md`, `CHANGELOG.md`, профильную документацию в `docs/` и версию в `package.json`, `package-lock.json`, `index.html`.
- Не добавлять в репозиторий `.env`, токены и пароли, `node_modules`, `dist`, временные файлы, архивы и копии проекта.
- Получить актуальную версию: `git fetch origin main && git checkout main && git pull --ff-only origin main`.

## Совместная работа ИИ-инструментов

Над проектом одновременно работают ChatGPT, OpenAI Codex и Claude Code. Эти правила обязательны для всех; Claude Code читает их через `CLAUDE.md`.

### Роли

- **ChatGPT** — архитектура, игровые механики, UX/UI, технические задания. Пишет ТЗ в GitHub Issue, код не меняет.
- **Codex** — реализация интерфейса и функций, исправление ошибок, UI-тесты.
- **Claude Code** — аудит, архитектура, сложные игровые механики, сохранения, производительность, ревью PR Codex.
- **Иван** — согласует планы и сливает PR в `main`. ИИ сливает PR только по прямому поручению Ивана и после зелёного `Project checks`.

### Ветки и PR

- Каждая задача — отдельная ветка от свежего `main`: `codex/<задача>` или `claude/<задача>`.
- Одна задача — один PR. В описании: ссылка на Issue, изменённые файлы, результаты проверок, что осталось.
- Перед PR ветка обновляется от `main` (`git fetch origin main` + rebase).
- Слияние только после зелёного `Project checks` и ревью второго инструмента.
- Значительные изменения (структура сохранений, `firestore.rules`, экономика, удаление функций) сначала описываются в Issue и согласуются с Иваном.

### Зоны файлов

Чтобы не править одни файлы одновременно:

| Зона | Основной исполнитель | Файлы |
| --- | --- | --- |
| Игровая логика и экономика | Claude Code | `src/game.ts`, `src/sphereProgress.ts`, `src/questEconomy.ts`, `src/personalQuests.ts`, `src/goalWorkspace.ts`, `src/planning.ts` |
| Сохранения и Firebase | Claude Code | `src/firebaseSave.ts`, `src/accountPersistence.ts`, `src/stateValidation.ts`, `src/backup.ts`, `firestore.rules` |
| Движок города и 3D | Claude Code | `src/cityLive/`, `src/components/room3d/`, `src/roomEngine.ts` |
| Страницы, компоненты, стили | Codex | `src/components/*.tsx`, `*.css` |
| UI-тесты и CI | Codex | `tests/*.mjs`, `.github/workflows/` |
| Общие файлы | по согласованию | `src/App.tsx`, `package.json`, `package-lock.json`, `index.html`, `CHANGELOG.md`, `AGENTS.md` |

Если задача требует файла из чужой зоны, это указывается в Issue заранее. Нельзя удалять или переписывать код, сделанный другим инструментом, без отдельного согласования.

### Передача работы

- Открытые задачи и их исполнитель — GitHub Issues с метками `codex`, `claude`, `chatgpt-spec`.
- Итог каждой задачи фиксируется в PR, а не только в чате: следующий инструмент читает PR и Issue, а не переписку.
- Номер версии и `CHANGELOG.md` обновляет последний PR перед выпуском версии.
