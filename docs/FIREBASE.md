# Аккаунты и сохранения PLAY YOUR LIFE

Используется существующий Firebase проект `play-your-life-872b1`, Web App `1:160735967041:web:0c6a59721e37a5950493c0`. Тариф Spark. Firebase Hosting, Storage, Analytics и платные резервные копии не подключаются.

## Настройка в Firebase Console
1. Authentication → Sign-in method → Email/Password включён.
2. Authentication → Settings → Authorized domains: добавить `vodolivan95.github.io`. Для локальной проверки добавить `localhost` и `127.0.0.1`.
3. Firestore Database Standard создан в Production mode.
4. Firestore Database → Rules: заменить правила содержимым `firestore.rules` из этой версии проекта и нажать Publish. Это обязательный шаг: создание базы в Production mode само по себе не разрешает приложению сохранять данные.
5. Проверить регистрацию двумя отдельными тестовыми аккаунтами: у каждого первоначально 0 XP, после выполнения квеста и повторного входа прогресс остаётся, на втором устройстве тот же аккаунт получает ту же игру.

Альтернативная публикация правил из этого репозитория при авторизованном Firebase CLI:
```sh
npx --yes --package firebase-tools@15.32.1 firebase deploy --only firestore:rules --project play-your-life-872b1
```

## Конфигурация
Для локальной разработки скопировать `.env.example` в `.env` и заполнить публичными параметрами существующего Web App из Project settings → General → Your apps → SDK setup and configuration.
`.env` исключён из Git. Публичная web-конфигурация существующего проекта также включена в клиент как значение по умолчанию для GitHub Pages. API key Firebase Web App не является административным секретом; доступ ограничивают Firebase Auth и Security Rules.
Сервисные аккаунты, приватные ключи, пароли пользователей и Admin SDK не используются в браузере.

## Модель данных
Документ `players/{Firebase Auth UID}`: `state` (вся личная игра), `revision` (версия), `updatedAt` (серверное время).
State сохраняет профиль, все сферы и их XP, цели/проекты/подзадачи, квесты, события прогресса, лайфкоины, покупки/награды, город, итоги месяца и даты активности. Уровни и достижения вычисляются прежней игровой механикой из сохранённого прогресса.
Auth хранит пароли; они не попадают в игровые документы или резервные копии.
Новая игра создаётся с 0 XP, 0 лайфкоинов, пустыми квестами и целями, без демо-наград.
Владелец может читать только свой документ. Перечисление пользователей, чужие документы, анонимный доступ и удаление документов клиентом закрыты.

### Разделённое сохранение
Чтобы документ не упирался в лимит Firestore, при записи в облако игра делится (`src/cloudSplit.ts`):

| Что | Где |
| --- | --- |
| Текущее состояние и события за последние 60 дней | `players/{uid}` |
| Более старые события, документ на месяц | `players/{uid}/history/{ГГГГ-ММ}` |
| Обложки целей и квестов, картинки своих наград | `players/{uid}/images/{goal\|quest\|reward}-{id}-{отпечаток}` |

В основном документе остаются указатели `historyIndex` (подписи месяцев) и `imageRefs`. Архив и обложки записываются до основного документа. При загрузке игра собирается обратно; если какой-то части не хватает или подпись не совпадает, загрузка останавливается, и неполная игра не сохраняется поверх полной. В памяти, локальных копиях и резервных копиях игра всегда полная. Старые сохранения переносятся автоматически при следующем сохранении; ненужные обложки удаляются после успешного сохранения. Подколлекции доступны только владельцу; архив нельзя удалить, обложку нельзя подменить под тем же id.

## Надёжность
Каждое изменение сразу сохраняется локально отдельно по UID и вкладке, затем отправляется в облако через 650 мс. Транзакция проверяет предыдущую revision. При конфликте автоматическая перезапись останавливается, обе версии можно скачать и явно выбрать.
При отсутствии сети локальная игра доступна, неподтверждённые изменения повторно отправляются после восстановления связи. Без локальной копии неудачная загрузка существующего аккаунта не заменяет его пустой игрой.
Ручное восстановление личной резервной копии переносит старую игру в текущий аккаунт только после выбора файла и подтверждения. Демо-копии в аккаунт не импортируются.
TickTick хранит OAuth-токен, сопоставления списков и связи задач отдельно на сервере подключения, по UID проверенного входа Firebase. Они загружаются на другом устройстве после входа в тот же аккаунт. В Firestore и игровую резервную копию токен TickTick не входит; браузер не сохраняет Firebase ID token для интеграции. Прежние локальные подключения остаются совместимыми, но для переноса настроек в аккаунт нужен новый OAuth-вход. Инструкция: [TICKTICK-SETUP.md](TICKTICK-SETUP.md).

### Живая синхронизация устройств (0.40.7)

Пока игра открыта, `CloudGame` (`src/AccountRoot.tsx`) подписан на документ `players/{uid}` через `onSnapshot`. Если в облаке появилась версия новее известной (`AccountSave.knownRevision`), вызывается `refresh()`: чужой прогресс подтягивается сразу. Обновление пропускается, если на этом устройстве есть неотправленные правки или идёт запись, поэтому локальные изменения не затираются, а при одновременных правках остаётся прежняя защита от конфликта. Ответы из локального кэша и собственные записи подписку не запускают. Минутный опрос, обновление при возврате на вкладку и при появлении сети остались запасным путём. Тесты: `tests/live-sync.test.ts`.

### Сохранение без ложных конфликтов (0.40.0)

Движок сохранения — `src/accountPersistence.ts` (`AccountSave`), отпечатки содержимого — `src/stateFingerprint.ts`.

- Каждая правка сразу пишется в локальный черновик. В облако она уходит через 650 мс после последней правки, а при непрерывной работе — не позже чем через 5 секунд. Когда вкладку скрывают или закрывают (`pagehide`, переключение на другую вкладку), неотправленное уходит сразу.
- Перед отправкой движок запоминает отпечатки отправляемых версий (до 24 последних). Если ответ сервера потерялся, многошаговая запись (основной документ, архив месяцев, обложки) оборвалась на середине или страницу закрыли до удаления черновика, облако оказывается «впереди» нашей ревизии, но с нашим же содержимым. Это узнаётся по отпечатку: ложного конфликта нет и лишней записи тоже. Повторных «догоняющих» попыток не больше трёх подряд.
- Чужая запись с другим содержимым, как и раньше, даёт явный конфликт: обе версии можно скачать и выбрать. Автоматической перезаписи нет, в том числе после перезапуска приложения.
- Любой выбор в конфликте и любое вытеснение старого черновика оставляют в браузере страховочную копию заменяемой версии (не больше трёх копий). Старые черновики других вкладок не теряются: открывается самый новый, остальные уходят в страховочные копии.
- Если место в хранилище браузера закончилось, черновик всё равно пишется: освобождается локальная копия облачной версии.
- После закрытия игры незавершённая многошаговая запись не продолжается.

## Без аккаунта (0.43.0)

Кнопка «Продолжить игру на этом устройстве» скрыта из обычного интерфейса: обычные игроки видят только вход и регистрацию, прогресс всегда сохраняется в облаке и синхронизируется между устройствами одного аккаунта. Код локального/офлайн-рендера (`App` без `userId`) в проекте остался — его использует набор автоматизированных браузерных проверок сайта (`tests/*-ui.mjs`), чтобы не создавать настоящие аккаунты Firebase и не писать в рабочую базу при каждой проверке. `src/AccountRoot.tsx` показывает кнопку только автоматизированному браузеру (`navigator.webdriver === true`); обычные браузеры этот признак не выставляют, обойти вход через интерфейс нельзя.

## Ограничения
Основной документ ограничен 800 КБ, архив одного месяца — 900 КБ, обложка — 160 КБ. Пользовательские файлы Firebase Storage не подключены на Spark. Для больших изображений используйте ссылки и скачивайте JSON резервной копии.
Облачные сохранения защищают от потери браузерной копии, но не являются платным сервисом резервных копий базы; встроенное скачивание JSON остаётся доступным.
Изоляция пользовательских данных не заменяет серверную систему защиты от накрутки XP. Текущая игра личная, общих рейтингов нет.

## Проверки
`npm run check`, `npm test`. Сохранения дополнительно проверяют 13 точечных сценариев (`tests/account-resilience.test.ts`: потерянный ответ, обрыв посреди записи, закрытие страницы, чужая запись, переполненное хранилище, потолок в 5 секунд) и случайные прогоны с имитацией сбоев и чужих записей (`tests/account-fuzz.test.ts`; по умолчанию 500 сценариев, длинный прогон — `FUZZ_SCENARIOS=9000`, повтор одного — `FUZZ_ONLY=режим:номер`). Проверяется: нет ложных конфликтов, чужие данные не перезаписываются молча, облако совпадает с экраном, последняя правка не теряется, не остаётся зависших черновиков.
GitHub Actions дополнительно запускает Firestore Emulator на тестовом проекте `demo-play-your-life` и проверяет правила для владельца, второго аккаунта и анонимного клиента. Тестовые документы не записываются в рабочий Firebase.
После публикации правил необходима реальная проверка регистрации/сохранения двух аккаунтов в рабочем проекте.
