# Аккаунты и сохранения PLAY YOUR LIFE

Используется существующий Firebase проект `play-your-life-872b1`, Web App `1:160735967041:web:0c6a59721e37a5950493c0`. Тариф Spark. Firebase Hosting, Storage, Analytics и платные резервные копии не подключаются.

## Настройка в Firebase Console
1. Authentication → Sign-in method → Email/Password включён.
2. Authentication → Settings → Authorized domains: добавить `vodolivan95.github.io`. Для локальной проверки добавить `localhost` и `127.0.0.1`.
3. Firestore Database Standard создан в Production mode.
4. Firestore Database → Rules: заменить правила содержимым `firestore.rules` из этой версии проекта и нажать Publish. Это обязательный шаг: создание базы в Production mode само по себе не разрешает приложению сохранять данные.
5. Проверить регистрацию двумя отдельными тестовыми аккаунтами: у каждого первоначально 0 XP, после выполнения квеста и повторного входа прогресс остаётся, на втором устройстве тот же аккаунт получает ту же игру.

Альтернативная публикация правил из этого репозитория при авторизованном Firebase CLI:
```sh
npx --yes --package firebase-tools@15.32.1 firebase deploy --only firestore:rules --project play-your-life-872b1
```

## Конфигурация
Для локальной разработки скопировать `.env.example` в `.env` и заполнить публичными параметрами существующего Web App из Project settings → General → Your apps → SDK setup and configuration.
`.env` исключён из Git. Публичная web-конфигурация существующего проекта также включена в клиент как значение по умолчанию для GitHub Pages. API key Firebase Web App не является административным секретом; доступ ограничивают Firebase Auth и Security Rules.
Сервисные аккаунты, приватные ключи, пароли пользователей и Admin SDK не используются в браузере.

## Модель данных
Документ `players/{Firebase Auth UID}`: `state` (вся личная игра), `revision` (версия), `updatedAt` (серверное время).
State сохраняет профиль, все сферы и их XP, цели/проекты/подзадачи, квесты, события прогресса, Life Coins, покупки/награды, город, итоги месяца и даты активности. Уровни и достижения вычисляются прежней игровой механикой из сохранённого прогресса.
Auth хранит пароли; они не попадают в игровые документы или резервные копии.
Новая игра создаётся с 0 XP, 0 монет, пустыми квестами и целями, без демо-наград.
Владелец может читать только свой документ. Перечисление пользователей, чужие документы, анонимный доступ и удаление документов клиентом закрыты.

## Надёжность
Каждое изменение сразу сохраняется локально отдельно по UID и вкладке, затем отправляется в облако через 650 мс. Транзакция проверяет предыдущую revision. При конфликте автоматическая перезапись останавливается, обе версии можно скачать и явно выбрать.
При отсутствии сети локальная игра доступна, неподтверждённые изменения повторно отправляются после восстановления связи. Без локальной копии неудачная загрузка существующего аккаунта не заменяет его пустой игрой.
Ручное восстановление личной резервной копии переносит старую игру в текущий аккаунт только после выбора файла и подтверждения. Демо-копии в аккаунт не импортируются.
TickTick подключение хранится отдельно по UID и не переносится через Firestore.

## Ограничения
Снимок ограничен 800 КБ, ниже лимита документа Firestore. Пользовательские файлы Firebase Storage не подключены на Spark. Для больших изображений используйте ссылки и скачивайте JSON резервной копии.
Облачные сохранения защищают от потери браузерной копии, но не являются платным сервисом резервных копий базы; встроенное скачивание JSON остаётся доступным.
Изоляция пользовательских данных не заменяет серверную систему защиты от накрутки XP. Текущая игра личная, общих рейтингов нет.

## Проверки
`npm run check`, `npm test`.
GitHub Actions дополнительно запускает Firestore Emulator на тестовом проекте `demo-play-your-life` и проверяет правила для владельца, второго аккаунта и анонимного клиента. Тестовые документы не записываются в рабочий Firebase.
После публикации правил необходима реальная проверка регистрации/сохранения двух аккаунтов в рабочем проекте.
