# Цель и карта этапов

Страница дорабатывает существующие `GoalsBoard`, формы планирования и состояние игры. Цели находятся в `state.goals`, этапы — в `goal.stages`, задачи — в `state.quests` с `goalId` и `stageId`. Отдельной базы или нового набора демонстрационных целей нет. Общие меню, верхняя панель, авторизация и 3D-спортзал не меняются. Максимум уровня игрока и каждой сферы — **100**; формулы XP сохраняются.

## Навигация

Логические адреса: `/goals/:goalId` и `/goals/:goalId/stages/:stageId`. На статическом GitHub Pages они используются после `#`: например, `#/goals/g/stages/s`. Это позволяет перезагружать прямую ссылку без серверной ошибки 404. Название, стрелка перехода и «Продолжить» используют ID выбранного этапа. Другая стрелка раскрывает задачи непосредственно в карте. Завершённые и запланированные этапы доступны; блокировка показывает условие. Владелец может изменить условие в форме этапа. Блокировка и пауза запрещают выполнение и частичный прогресс задач также через общие функции квестов.

## Источники прогресса и наград

- Числовая цель сохраняет `current / target`. Добавление пустых этапов не меняет 68% или другой сохранённый результат.
- Для режима задач процент считается по обязательным задачам (`required !== false`), с весом `weight`, по умолчанию 1. Если есть частичная задача, используется её `currentValue / targetValue`.
- У пустой цели в режиме задач сохраняется последний результат. При явном переходе из числового режима исходный результат остаётся также в `manualProgress`.
- При загрузке процент целей с обязательными задачами приводится к тому же расчёту. Миграция не выдаёт XP и не выдумывает события.
- Этап с завершением по задачам закрывается после всех обязательных задач. Ручное завершение используется для результата без задач. Новая обязательная задача открывает автоматически завершённый этап повторно.
- XP цели выдаётся один раз через существующий `rewarded`. XP и Life Coins этапа — сумма существующих наград его задач. Дополнительный бонус за этап не вводится. Название и редкость результата — пользовательские необязательные поля, без вымышленных трофеев и автоматического создания предметов в магазине.
- После начала прогресса задачи её награда, сложность и сфера зафиксированы по существующим правилам. При копировании этапа задачи получают новые ID и сброшенные отметки выполнения, без новых начислений.

История использует сохранённые события, ID цели/этапа/задачи и реальные известные даты создания. Событие с ID остаётся у исходной цели даже после перемещения задачи. Старые награды без ID связываются по названию и сфере только при однозначном соответствии. Для старого этапа без даты создания дата не подставляется.

План-факт использует сроки и даты выполнения; XP — фактические начисления; история процентов — отдельные сохранённые снимки цели и этапа. Расстояния между точками соответствуют реальным интервалам времени; одиночная точка также видна. Под графиками доступны исходные значения. Выполненные задачи без даты не получают вымышленную дату. Отсутствие исторических данных показывается явно.

После завершения активного этапа индикатор и раскрытие переходят к следующему доступному этапу. Пауза, условия доступа и будущая дата начала учитываются. Ручное сворачивание не отменяется периодическим обновлением страницы.

## Сохранение

Изменения передаются через существующий `onChange` и стандартное состояние игры. Локальное сохранение, очередь аккаунта, Firestore `players/{uid}`, проверка версии и конфликтов остаются существующими. Новые поля допускаются валидатором резервных копий. Удаление этапа оставляет задачи в цели без этапа; удаление цели оставляет задачи без цели. Награды и история сохраняются. Перед удалением показывается подтверждение.

Редактирование названия, описания, заметок или обложки сохраняет исходную точность сроков, включая секунды. Редактирование задачи без дат не назначает ей новые сроки. При отказе сохранения окно остаётся открытым с введённым текстом.

## Проверки

```bash
npm run check
npm test
node --experimental-strip-types --test --test-isolation=none tests/*.test.ts
npm run test:goals-ui
npm run test:quests-ui
npm run test:live-city
```

`test:goals-ui` использует отдельные браузерные контексты и тестовую локальную игру при ширинах 1440, 768, 390 и 360 px. Проверяет отдельные переходы «Продолжить» и стрелки для разных этапов, возврат браузера назад/вперёд, раскрытие, вкладки, фильтр задач, календарь, частичный и полный прогресс, награды, управление этапами и перезагрузку. Дополнительно проверяет точность сроков, отсутствие новых дат при редактировании старой задачи и сохранение введённого значения при отказе в приостановленном этапе. Для системного Chromium можно задать `LIFEGAME_CHROMIUM_PATH`.

В GitHub Actions существующая проверка Firestore Emulator дополнена сценарием сохранения цели, этапов, заметок, прогресса, порядка и однократных наград через настоящий SDK. Используется только `demo-play-your-life` и тестовые UID. Правила Firestore не меняются.

Проверки эмулятора и тестов не подтверждают доступ к реальному Firebase, вход в производственный аккаунт или публикацию GitHub Pages. Код в ветке, публикация сайта и пользовательский прогресс — независимые процессы.
