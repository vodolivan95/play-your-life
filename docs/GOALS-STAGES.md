# Цели и этапы

Доработка использует существующий GameState и документ Firestore players/{uid}. Новые коллекции для целей, этапов и задач не создаются. Старые данные и фотографии image сохраняются. История событий, настройка обложки, обязательность и повторение задач — дополнительные поля. stageAchievements хранит полученные трофеи отдельно от удаляемого этапа.

Маршруты: /goals, /goals/:goalId, /goals/:goalId/stages/:stageId, /goals/:goalId/stages/:stageId/tasks/:taskId. На Pages прямое открытие восстанавливается через 404.html, на Vercel — через rewrite. Последовательный этап проверяет предыдущий при открытии и выполнении.

Календарь использует местные календарные даты, неделю с понедельника и фактическую длину месяцев. Временной прогресс отличается от выполнения обязательных задач. Графики используют события выполнения/отмены и известные completedAt старых задач. Прогноз появляется только при выполнении задач хотя бы в два разных дня; группировка графика не меняет прогноз.

## Награды

Отмена возвращает XP и монеты конкретной задачи. Если монеты уже потрачены и баланс недостаточен, отмена не выполняется. Зафиксированная стоимость задачи остаётся неизменной. При повторном выполнении возвращается та же награда. Однократные награды цели, этапа и серии дней сохраняются как достигнутые вехи, повторно не начисляются. Награда этапа ограничена 0–500 XP и 0–500 монет; выплаченную стоимость нельзя редактировать. Дублирование создаёт новые ID этапа и задач без истории выполнения и выплат.

Облачные возвраты и новые награды этапов включаются через VITE_GOAL_ECONOMY_ENABLED=true только после проверки и публикации firestore.rules в существующий проект Firebase. До этого интерфейс явно показывает ограничение, обычное выполнение задач и планирование продолжают работать. Версия документа и транзакции защищают повторные и одновременные запросы. Изменённые правила не опубликованы автоматически.

## Обложки

Goal.cover содержит URL, путь, размер и параметры кадрирования. Один объект используется в списке целей, баннере цели и всех её этапах. Исходные байты файла не пересжимаются, Base64 в Firestore для новых обложек не записывается. Форматы JPG/PNG/WebP, до 20 МБ и 40 мегапикселей. Удаление обложки возвращает стандартное изображение, физический общий файл не удаляется автоматически.

VITE_GOAL_STORAGE_ENABLED=true допустим только после подтверждения постоянного Storage и owner-only правил. storage.goal-covers.rules — отдельный проект правил для нового пути, не замена всех правил существующего bucket. Spark/Blaze не переключается. Пока постоянное хранилище не подтверждено, загрузка доступна как предпросмотр с явным сообщением «не сохранено», без ложного сообщения об успехе.

Напоминания показываются в приложении; фоновые push-уведомления не подключены. Графики не создают демонстрационных событий. Изображения города и UI-иконки не менялись. Максимальный уровень сферы — 50, накопленный XP сохраняется при миграции прежней модели.

## Проверки

npm run check, npm test, node tests/goals-ui.mjs, npm run test:quests-ui.
Firestore: firebase emulators:exec --only firestore --project demo-play-your-life "node --experimental-strip-types --test tests/firebase-rules.test.mjs".

UI-тесты используют отдельные локальные профили, а не пользовательские аккаунты. Проверяются 1440/360/390 px, прямые ссылки, перезагрузка, календарь, заметки, возвраты, диаграммы и блокировка. Production Firebase и реальная загрузка файла требуют доступа к существующему проекту и подтверждённого хранилища.
