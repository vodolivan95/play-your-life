## Исправления перед слиянием

- В исходном #309 пропущена закрывающая скобка `stuckTasks()` перед `ExecutionOverview`. Из-за ошибки не разбирался `planner.ts` и не загружалось приложение.
- По замечаниям Codex Review к #309 фокус восстанавливается при обычном открытии обзора и смене недели. История читает сохранённые `totals` и `projects`, а не пересчитывает их по изменённой игре. Редактирование исторического обзора требует отдельного действия. Список проблемных задач истории берётся из сохранённых ID; имена доступных задач отражают текущее состояние, старые имена модель обзора не хранит.
- Воспроизведена мобильная регрессия #263: общие `.pyl-overlay`-стили загружались только вместе с ленивой страницей задач. Окно задачи из сферы оказывалось под нижней навигацией. Общие стили вынесены в `Overlay.css` и подключены до загрузки разделов; генератор тёмной темы учитывает новый файл. Проверка не ослабляется принудительным кликом.
- Бюджеты стартовых JS/CSS снижены до 420/70 КБ. Замер после разделения: 388.2/53.8 КБ против 463.7/86.3 КБ в main 0.79.0. Общий бюджет — 1000 КБ при замеренных 988.0 КБ: отдельные gzip-файлы сжимаются хуже одного общего. Первая загрузка меньше примерно на 108 КБ.
- Исправлены шаблонные заглушки журнала 0.80.0, обновлены генерируемые стили.

## Проверки и ограничение публикации

Локально выполнены `npm run check` и `npm test` (605 passed, 0 failed, 0 skipped). Новый `npm run test:weekly-review-ui` проверяет восстановление фокуса после открытия и смены недели, неизменность исторического снимка после изменения задач/проектов и явный переход к пересчёту, на ПК и телефоне. Он включён в job `sections-ui` GitHub Actions.

После исправления общих стилей локально прошли `test:spheres-ui`, `test:smoke-ui`, `test:quests-ui`, `test:tasks-calendar`, `test:goals-ui` (1440, 768, 390 и 360 px), повторный `test:weekly-review-ui` и `check:budgets`. Тест календаря ждёт загрузки сводки перед подсчётом элементов и закрывает окно актуальной кнопкой «Сохранить». Окончательный статус всех сценариев фиксируется в GitHub Actions и итоговом отчёте. Сборку, которая перегенерирует CSS и вызывает HMR, не следует запускать одновременно с браузерным обходом dev-сервера.

Перед обновлением main требуется успешный `Project checks` для точного итогового коммита. Доступ GitHub API ограничен сетью среды; публичные страницы PR/Actions доступны для чтения, Git используется для отправки ветки и слияния без force push. Проверки на фикстурах не подтверждают работу реальных аккаунтов Firebase/TickTick. Публикация Pages и Vercel проверяются отдельно от сохранения кода в main.
