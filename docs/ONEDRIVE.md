Начальная версия 0.86.0 использовала MSAL Browser и локальную привязку аккаунта к UID. Этого недостаточно для требования серверной проверки каждой операции. В 0.86.1 Microsoft OAuth и токены перенесены на сервер. При первом открытии удаляются оставшиеся sessionStorage-ключи старой MSAL-интеграции; игровые данные не меняются.

## Архитектура и безопасность

1. Браузер получает свежий Firebase ID token от текущего пользователя и отправляет его серверу OneDrive по HTTPS. Для API это Authorization header; для начала OAuth — тело верхнеуровневого POST. В URL токенов нет.
2. Worker проверяет Firebase JWT и сам выбирает Durable Object по проверенному UID. `uid`, `userId`, заголовки и идентификаторы из браузера не выбирают чужое хранилище. Административного доступа к чужим подключениям нет.
3. MSAL Node (`ConfidentialClientApplication`) выполняет Authorization Code Flow с PKCE. По умолчанию authority — `consumers`, поддерживаются личные Microsoft-аккаунты. Для организаций предусмотрен `MICROSOFT_TENANT=common`/`organizations` при совместимой регистрации Entra.
4. OAuth state содержит случайный nonce и непрозрачный идентификатор объекта. Он имеет срок 10 минут, используется один раз и сверяется с HttpOnly/Secure/SameSite=Lax cookie исходного браузера. Верхнеуровневый POST устанавливает эту cookie без сторонних cookie. Microsoft callback не зависит от активного окна приложения; связь устанавливается в исходном проверенном UID.
5. PKCE verifier и весь кеш MSAL (включая refresh token) сохраняются с AES-256-GCM, случайным IV и привязкой ciphertext к объекту пользователя. Ключ шифрования и client secret находятся только в Worker Secrets. Логи MSAL отключены.
6. Сервер получает Microsoft-токен через `acquireTokenSilent`, сохраняет обновлённый кеш и обращается к Graph. Браузер не получает Microsoft-токены или подписанные upload URL. Graph nextLink проверяется по origin/пути. Разрешены только операции OneDrive; произвольные URL и `/users/...` отвергаются.
7. Загрузка идёт через непрозрачные серверные upload handles, привязанные к тому же UID. Контент скачивается через сервер; при переходе на CDN Microsoft Authorization header не передаётся. Содержимое файлов не хранится в базе.
8. Отключение удаляет серверный кеш, pending OAuth и upload handles. Файлы OneDrive не удаляются. Следующее подключение требует Microsoft-входа. Разрешение приложения в Microsoft можно отдельно отозвать в настройках Microsoft-аккаунта.

Microsoft Graph permissions: **delegated `User.Read`, `Files.ReadWrite`**. `User.Read` используется для read-only проверки `/me` и имени/почты профиля; стандартные OAuth scopes MSAL (`openid`, `profile`, `offline_access`) нужны для входа/обновления. Отдельный общий Microsoft-аккаунт не используется. Доступ к конкретному файлу дополнительно проверяет Microsoft; ссылка во вложении не предоставляет разрешений. Открытие ссылки другим пользователем требует его собственного подключения и прав Microsoft.

## Расположение папок по скриншоту пользователя

На телефоне — две крупные плитки, счётчик внутри папки, однострочное имя, дата и меню «⋯» ниже. На ПК сетка увеличивает число колонок. На узком экране дополнительные команды открываются кнопкой «Инструменты», чтобы папки оставались выше. Скриншоты ниже сняты на **изолированных тестовых метаданных**, это не файлы пользователя: [светлая тема](design/onedrive-folders-mobile.png), [тёмная тема](design/onedrive-folders-mobile-dark.png).

## Что реализовано

- Подключение/повторное подключение, явный выбор Microsoft-аккаунта, отображение аккаунта и квоты, отключение.
- Папки, хлебные крошки, уровень выше, прямые ссылки, мобильное открытие одним нажатием.
- По скриншоту пользователя от 17 ноября: две крупные папки в ряд на телефоне, название и дата под иконкой, меню «⋯» снизу, число элементов внутри папки. Цвет папки настраивается локально в Play Your Life (UID/drive/item); Graph-цвет Microsoft не имитируется и не синхронизируется.
- Плитка/список; сортировка по названию, размеру и изменению; папки перед файлами. Сортировка относится к загруженной части каталога.
- Постраничная загрузка по 100 объектов и ленивые миниатюры. При открытии не перечисляется весь OneDrive и не скачивается содержимое файлов.
- Создание папок без молчаливой замены, переименование, выбор папки для переноса, удаление с подтверждением, свойства, ссылка с существующими правами доступа.
- Множественное выделение, последовательное массовое перемещение/удаление. При ошибке показано число уже выполненных операций; общей транзакции Graph нет.
- При наличии eTag переименование/перенос/удаление отправляют If-Match: изменения с другого устройства требуют обновить список.
- File picker и Drag & Drop. Upload session для непустых файлов, блоки по 5 МиБ (кратно 320 КиБ), прогресс и отмена. При обрыве повторный выбор того же файла в открытом разделе продолжает загрузку с серверной позиции. Автоматической повторной отправки мутации нет. Пустой файл создаётся отдельно с запретом перезаписи.
- Встроенный просмотр JPG/JPEG/PNG/WEBP, PDF, TXT/Markdown/CSV/LOG/JSON и MP4/WEBM/OGG. Markdown показан как текст; HTML/скрипты не выполняются. Office открывается в Microsoft 365.
- Поиск Graph, типы файлов, переход к расположению. Если поиск отвечает 400/501, доступен явно обозначенный поиск названий в текущей папке с постраничным продолжением.
- Ограниченный кеш метаданных в памяти текущего экземпляра раздела (до 20 каталогов/поисков), отметка сохранённых данных при сбое, запрет облачных мутаций без сети.
- Delta API начинает с `token=latest`, без полного обхода диска. Проверка при фокусе и раз в две минуты, когда раздел открыт/виден. Изменения сбрасывают кеш и обновляют текущую папку; при неподдерживаемом/истёкшем delta используется обычное чтение.
- `＋ OneDrive` во вложениях задачи, файл/папка OneDrive в материалах проекта и избранное. В игровом сохранении остаются только `driveId`, `itemId`, название и признак папки. Папки автоматически не создаются. Старые сохранения совместимы.

## Регистрация Microsoft Entra — действия владельца

Прежняя инструкция 0.86.0 про SPA и `VITE_MICROSOFT_CLIENT_ID` заменена серверной схемой. Клиентский ID не требуется фронтенду.

Перед регистрацией: для административного входа нужен доступ к настоящему каталогу Entra с правом регистрации приложений. Личный Outlook без связанного каталога может получить AADSTS50020 для ADIbizaUX в Microsoft Services; это не OAuth вашего OneDrive. Сначала выберите собственный каталог или получите/создайте его по [инструкции Microsoft](https://learn.microsoft.com/en-us/troubleshoot/entra/entra-id/app-integration/error-code-aadsts50020-user-account-identity-provider-does-not-exist).

1. Откройте Microsoft Entra admin center → **App registrations → New registration**. Назовите приложение Play Your Life OneDrive. Выберите тип аккаунтов с поддержкой личных Microsoft-аккаунтов. Можно выбрать организационные + личные, оставив серверный authority `consumers` до отдельной проверки организаций.
2. Сохраните **Application (client) ID**. Это публичный идентификатор; не подставляйте случайный UUID.
3. Выберите HTTPS-origin будущего Worker (Workers dashboard показывает его для имени `play-your-life-onedrive`) или собственный домен. В **Authentication → Add a platform → Web** добавьте точный адрес этого сервера с путём `/callback`. Это серверный **Web redirect URI**, а не SPA URI и не адрес GitHub Pages. Путь/схема/домен должны точно совпасть с `BRIDGE_URL + /callback`.
4. В **Certificates & secrets → Client secrets** создайте секрет. Скопируйте **Value** в защищённое хранилище/Worker Secret `MICROSOFT_CLIENT_SECRET`. Поле Secret ID вместо Value не подойдёт. Секрет не отправляйте в чат и не добавляйте в Vite, git или `.env` репозитория. Запишите срок действия для последующей замены.
5. В **API permissions → Microsoft Graph → Delegated permissions** добавьте **User.Read** и **Files.ReadWrite**. Application permissions не нужны. Не запрашивайте пароль Microsoft в Play Your Life.
6. Настройте серверные переменные и секреты по таблице ниже, разверните Worker. При регистрации допускается сначала выбрать адрес Worker, затем обновить точный redirect URI после его создания.
7. Укажите адрес сервера в `VITE_ONEDRIVE_BRIDGE_URL` для frontend build, пересоберите preview. Войдите в Play Your Life → «Мой диск» → «Подключить OneDrive». Microsoft должен запросить согласие на ваши файлы.
8. Пройдите live-матрицу ниже двумя разными пользователями до публикации. Корпоративные аккаунты проверяются отдельно при смене authority.

## Переменные и секреты

| Где | Имя | Значение |
| --- | --- | --- |
| Worker variable | `MICROSOFT_CLIENT_ID` | Реальный Application (client) ID из Entra. |
| Worker secret | `MICROSOFT_CLIENT_SECRET` | Реальный Value секрета Web-приложения. |
| Worker secret | `TOKEN_ENCRYPTION_KEY` | 32 случайных байта в виде 64 hex-символов; сгенерируйте `openssl rand -hex 32`. Не публикуйте. При замене ключа пользователи подключаются заново. |
| Worker variable | `BRIDGE_URL` | Точный HTTPS-origin Worker без завершающего `/`, query и пути. |
| Worker variable | `APP_URL` | Адрес frontend с завершающим `/`; задаёт разрешённый CORS origin и адрес возврата. В wrangler.toml указан существующий GitHub Pages URL. Для preview/локального запуска используйте его собственный адрес. |
| Worker variable | `FIREBASE_PROJECT_ID` | Существующий Firebase project ID приложения; уже задан в wrangler.toml. |
| Worker variable | `MICROSOFT_TENANT` | `consumers` по умолчанию; `common`/`organizations` только при соответствующей регистрации. |
| Frontend build | `VITE_ONEDRIVE_BRIDGE_URL` | Только публичный HTTPS-origin Worker. Client secret и ключ шифрования здесь недопустимы. |

Worker также требует binding `ACCOUNTS` с классом `OneDriveAccount`; binding и миграция уже описаны в `integrations/onedrive/wrangler.toml`. Firebase Admin credential не нужен.

## Локальный запуск

- Node 24; `npm ci`, затем `npm run dev`. Для фронтенда задайте `VITE_ONEDRIVE_BRIDGE_URL` в своём локальном окружении или `.env.local` (не коммитить). Без сервера раздел честно показывает отсутствие настройки; демонстрационные файлы не подставляются.
- Для серверной разработки используйте Wrangler 4.147.0, конфигурацию `integrations/onedrive/wrangler.toml`, свои server variables и локальные секреты Wrangler. Для локального OAuth зарегистрируйте точный callback URI, разрешённый Entra; при необходимости используйте отдельный HTTPS-домен разработки. `APP_URL` должен совпадать с dev frontend, чтобы сработала проверка Origin.
- Без Entra/облака можно выполнить `node --experimental-strip-types --test tests/onedrive*.test.ts` и `node tests/onedrive-ui.mjs`. Они используют явно изолированные фикстуры и не подтверждают работоспособность личного аккаунта Microsoft.
- `npm run check` включает frontend, TickTick Worker и OneDrive Worker typecheck. `npm test` включает профильные тесты. `npm run check:budgets` запускается после сборки.

## Развёртывание

Существующие Firebase/авторизация и TickTick не мигрируются. Новый Worker разворачивается отдельно. Для ручного деплоя авторизуйтесь в Cloudflare своим способом, задайте переменные конфигурации, затем `npx wrangler@4.147.0 secret put MICROSOFT_CLIENT_SECRET --config integrations/onedrive/wrangler.toml` и аналогично `TOKEN_ENCRYPTION_KEY`; выполните `npx wrangler@4.147.0 deploy --config integrations/onedrive/wrangler.toml`. Не передавайте секреты аргументами командной строки. `BRIDGE_URL` и `MICROSOFT_CLIENT_ID` можно задать как обычные vars в конфигурации/Cloudflare.

Для GitHub Actions подготовлен `.github/workflows/onedrive.yml`. Он отключён, пока repository variable `ONEDRIVE_ENABLED` не равна `true`. Нужны:

- Repository variables: `MICROSOFT_CLIENT_ID`, `VITE_ONEDRIVE_BRIDGE_URL`, `ONEDRIVE_ENABLED`, при необходимости `MICROSOFT_TENANT` (`consumers` по умолчанию).
- Repository secrets: `MICROSOFT_CLIENT_SECRET`, `ONEDRIVE_TOKEN_ENCRYPTION_KEY`, существующие `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`.
- Workflow собирает именно коммит main, для которого прошёл `Project checks`; ручной запуск также доступен после явной настройки. В предоставленном wrangler.toml `APP_URL` соответствует GitHub Pages; перед использованием другого frontend укажите его адрес в серверной конфигурации.
- Pages получает `VITE_ONEDRIVE_BRIDGE_URL` из repository variables. Для Vercel укажите переменную в нужном Preview/Production Environment и пересоберите сайт. Сервер должен разрешать этот frontend origin; для изолированного preview используйте отдельный Worker с теми же требованиями шифрования и callback.

Слияние PR и production-деплой требуют отдельного поручения владельца. Адрес рабочего модуля появится только после настоящего деплоя/проверки; существующий preview без настроенного сервера не доказывает подключение OneDrive.

## Проверки и границы

Автоматические тесты проверяют настоящую криптографию AES-GCM, подписи тестовых Firebase JWT, серверную маршрутизацию двух пользователей и второго устройства, подмену UID, одноразовый/чужой OAuth state, PKCE и cookie, границы Graph/CDN, отсутствие provider-токенов в ответах, привязку upload handle, отмену/продолжение загрузки, запрет повторных мутаций и безопасные ссылки в сохранениях. Границы MSAL/Microsoft в этих тестах замоканы. UI-тест содержит 100+ объектов с несколькими страницами, папки/просмотр/массовые операции/загрузку/поиск/ошибки/потерю сети и четыре ширины экрана. Результаты полного запуска фиксируются в PR и отчёте проверки.

Остающиеся ограничения:

- Реальные Microsoft OAuth, silent refresh, upload/CDN, квота и доступ двух Microsoft-аккаунтов требуют зарегистрированного приложения и live-проверки.
- Кеш метаданных не сохраняется после закрытия/перезагрузки раздела или выхода. Контент offline не кешируется. Закрытый сайт не синхронизируется; нет фонового push/delta.
- Возобновление загрузки доступно в том же открытом разделе до истечения upload session. Отмена удаляет handle и запрашивает отмену у Microsoft; при потере сети незавершённая provider-сессия истечёт сама. После перезагрузки проверяйте список перед новой отправкой; последний ответ может потеряться после фактического завершения.
- Просмотр текстов ограничен 2 МиБ, изображений/PDF/видео — 50 МиБ; большие файлы и Office открываются в Microsoft 365. Скачивание использует Blob браузера; для очень больших файлов предпочтительно открытие Microsoft 365. Поддержка видео/PDF зависит от браузера. Office-редактор не создаётся.
- Сортировка/фильтры работают по загруженным страницам. Вкладка общего фотоальбома не создаётся. Если Microsoft поддерживает search, поиск может учитывать содержимое по правилам Graph; fallback по названию ограничен текущей папкой.
- Общая папка другого диска открывается в Microsoft после проверки доступа к её метаданным; полноценный менеджер ориентирован на личный `/me/drive`. Ссылки никогда не создают общего доступа автоматически.
- Delta/feed и корпоративные аккаунты зависят от возможностей Microsoft; при ошибке доступны явное обновление и повторное подключение.
