# Публикация через GitHub Pages

Адрес сайта: <https://vodolivan95.github.io/play-your-life/>.

## Обычная публикация

Публикация настроена в `.github/workflows/pages.yml`. При успешном завершении workflow **Project checks** для ветки `main` запускается сборка GitHub Pages. Деплой собирает именно SHA коммита, который прошёл CI, а не более новый `main`, появившийся во время проверки. Если CI завершился ошибкой, автоматическая публикация не запускается.

В обычной работе достаточно отправить изменения в `main` или слить Pull Request после проверок. Откройте **Actions** и дождитесь завершения **Deploy to GitHub Pages**; затем проверьте сайт по адресу выше. После первого включения Pages владелец репозитория должен выбрать **Settings → Pages → Build and deployment → Source → GitHub Actions** и разрешить Actions во вкладке **Actions**, если они ещё отключены.

В workflow есть ручной запуск (`workflow_dispatch`). Он выполняет собственные unit-тесты и `npm run check`, но не ожидает полный workflow **Project checks** с браузерными и Firestore Emulator сценариями. Используйте его только осознанно; обычный путь через CI предпочтительнее.

## Сборка и локальная проверка

GitHub Actions задаёт `VITE_BASE_PATH=/play-your-life/`, чтобы пути ресурсов работали в подкаталоге GitHub Pages. Для локальной проверки опубликованной сборки:

```sh
VITE_BASE_PATH=/play-your-life/ npm run check
VITE_BASE_PATH=/play-your-life/ npm run preview
```

Откройте <http://localhost:4173/play-your-life/>. Цели и этапы используют адреса после `#`, например `#/goals/g/stages/s`; прямую ссылку можно обновить без серверных настроек SPA.

## Сайт и игровые данные — раздельные вещи

Исходники в GitHub, опубликованная сборка Pages и прогресс игрока хранятся отдельно. Гостевая игра привязана к браузерному хранилищу и не переносится автоматически между устройствами. Личная игра вошедшего пользователя использует Firebase при корректной авторизации, доступной сети и опубликованных правилах Firestore. Деплой сайта не переносит пользовательские данные и сам по себе не доказывает, что производственная синхронизация работает.
