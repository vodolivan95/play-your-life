# Проверки качества

Что проверяется автоматически и где. Всё запускается в GitHub Actions (`Project checks`) на каждый push и PR; локально — теми же командами.

| Что проверяется | Команда | Где в CI |
| --- | --- | --- |
| Стиль кода, типы, сборка | `npm run check` | `check` |
| Вес сборки | `npm run check:budgets` (после сборки) | `check` |
| Игровая логика, сохранения, TickTick, общие проверки проекта | `npm test` | `check` |
| Правила Firestore в эмуляторе | `tests/firebase-rules.test.mjs` | `firestore-rules` |
| Обход всех разделов на ПК и телефоне | `npm run test:smoke-ui` | `sections-ui` |
| Ключевые итоги и отчёт месяца | `npm run test:key-results-ui`, `npm run test:month-report-ui` | `sections-ui` |
| Задачи, цели, тема, сферы, TickTick | `npm run test:quests-ui`, `test:tasks-calendar`, `test:goals-ui`, `test:theme-ui`, `test:spheres-ui` | `quests-ui` |
| Живой город | `npm run test:live-city` | `live-city-ui` |

## Общие проверки проекта

`tests/quality-gates.test.ts` запускается вместе с `npm test` и ловит то, что легко забыть:

- версия одна во всех местах: `package.json`, `package-lock.json`, `index.html`, `AGENTS.md`, первая запись `CHANGELOG.md`;
- в репозитории нет `.env`, ключей, токенов, архивов, `node_modules`, `dist` и файлов тяжелее 6 МБ; секрет TickTick не попадает в код сайта;
- каждый браузерный тест из `tests/*.mjs` подключён к CI (иначе тест написан, но никогда не запускается), в CI есть проверка веса и обход разделов;
- в коде нет `console.log`, `debugger` и `test.only`;
- у страницы задан язык и масштаб телефона, правила Firestore не открывают данные всем.

## Обход разделов

`tests/smoke-ui.mjs` открывает сайт на ПК (1440 × 1000) и телефоне (390 × 844) и проходит все разделы меню, вкладки сфер, «Мои задачи» (Входящие, Список, Календарь и все виды календаря), «Ключевые итоги», магазин и дерево навыков, затем перезагружает страницу. Запросы к чужим сайтам (погода, шрифты, Firebase) блокируются: игра обязана открываться и без них.

Тест падает, если на любом шаге есть:

- ошибка скрипта или `console.error` своего сайта (в dev-режиме сюда попадают предупреждения React);
- запрос своего сайта, который не удался или вернул 4xx/5xx;
- пустой экран (в основной области почти нет текста) или показано сообщение «раздел не открылся»;
- горизонтальная прокрутка на телефоне.

Снимки каждого раздела — `work/smoke/*.png` (в CI сохраняются как `sections-previews`). `SMOKE_PREVIEW=1 npm run test:smoke-ui` проверяет собранную версию (`npm run build` → `vite preview`), а не dev-сервер.

## Вес сборки

`scripts/check-budgets.mjs` после `npm run build` сравнивает сжатый (gzip) размер с бюджетом:

| Что | Бюджет | Было в 0.39.0 |
| --- | --- | --- |
| Главный скрипт | 460 КБ | 415 КБ |
| Главные стили | 85 КБ | 75 КБ |
| Самый тяжёлый подгружаемый скрипт (3D) | 310 КБ | 277 КБ |
| Все скрипты и стили | 900 КБ | 808 КБ |
| Самый тяжёлый файл (картинка, модель) | 3 МБ | 2,6 МБ |
| Вся сборка | 40 МБ | 32,2 МБ |

Если вес вырос осознанно, число поднимают в скрипте, а причину записывают в `CHANGELOG.md`.

## Защита от белого экрана

`src/components/ErrorBoundary.tsx`: если один раздел ломается при показе, вместо пустой страницы появляется сообщение «Этот раздел не открылся» с кнопками «Попробовать снова» и «Обновить страницу»; меню и остальные разделы работают, сохранение продолжается. Сообщение пропадает при переходе в другой раздел. Второй слой на всём приложении (`src/main.tsx`) показывает «Игра не открылась». Данные компонент не меняет.
