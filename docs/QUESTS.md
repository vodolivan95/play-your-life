# Личные квесты и привычки

Вкладка «Квесты» расширяет существующие `GameState.quests`, XP, баланс `coins` и сохранение `players/{uid}`. Девять сфер, здания, комнаты, планирование и TickTick остаются прежними. Рекомендации — идеи для создания личного квеста, а не общий список задач аккаунтов.

## Возможности

- Мастер из шести коротких шагов: название и описание, сфера, фотография, цель и сроки, награда, проверка.
- Life Coins: целые 0–100 у пользовательского квеста; 0–10 у привычки. XP определяется существующей сложностью: 5/10/20/35/50; у привычки 5 XP.
- Прогресс, редактирование, подтверждение удаления, поиск, статус, фильтры сфер и сортировка.
- Награда, сложность, виртуальный предмет и сфера фиксируются после прогресса. Выполненный квест повторно не награждается.
- Персональные привычки: 12 иконок, цель, единица, выбранные дни недели, ежедневная история, текущая и лучшая серии.
- Первый шаг переиспользует имеющееся достижение. Новые «Квестомастер», «Постоянство», «Легенда квестов» пока закрыты; их правила не добавлены. Остальные старые достижения сохранены.
- Шесть разрешённых базовых предметов; растение передаётся в существующий инвентарь SPORT и устанавливается обычными средствами комнаты. Остальным предметам нужны будущие 3D-модели.
- Недельная цель 10 выполнений — ориентир без дополнительного начисления монет.

## Фотография

Поддержан системный выбор JPG/JPEG, PNG, WEBP до 5 МБ и 40 мегапикселей, проверка декодирования, замена, удаление выбранной фотографии, предпросмотр с `object-fit: cover` и освобождение Object URL.

В существующем проекте есть имя Firebase Storage bucket, но нет подтверждённой инфраструктуры загрузки, Storage Rules или разрешённого тарифа. Поэтому **выбранная фотография пока не сохраняется**: карточка получает существующее здание сферы. Старые допустимые растровые обложки из сохранения продолжают отображаться. Base64-фотографии не добавляются в Firestore вместо Storage.

Для постоянных обложек требуется отдельно подтвердить доступность существующего bucket и тариф, добавить Storage Rules с UID и ограничениями типов/размера и подключить загрузку. Новый Firebase Project, Blaze и платные сервисы не включались.

## Хранение и защита

Существующий документ `players/{uid}` остаётся единственным облачным сохранением игры. В `state` добавлены необязательные `habits`, `habitCompletions`, `coinTransactions`, `rewardInventory`. Старые резервные копии читаются без сброса данных. Кэш аккаунтов уже разделён по UID.

Соседние поля документа `economyRecords`, `recordChanges`, `rewardProofs` — проверяемые определения и свидетельства наград для Security Rules, а не вторая система квестов. Правила запрещают доступ другому UID, награды вне лимита, откат выплаченного статуса, удаление засчитанных дней и рост баланса без проверенного завершения. Каждое начисление требует выполненного личного источника и записи журнала с тем же UID и суммой. Поля определения остаются зафиксированными после начала прогресса. Для старых квестов создаются записи без повторной выплаты.

Статус источника, баланс и журнал выплаты записываются в одной Firestore transaction с проверкой `revision`. Предварительная регистрация определения ничего не начисляет. Очереди из многих действий разделяются на транзакции до трёх изменённых определений; в промежуточных снимках ещё не выплаченные завершения остаются активными. Привычка не получает две выплаты за одну дату. Конфликт версий не перезаписывает другую сессию.

Финансовые свидетельства сохраняются после удаления карточки, чтобы удаление и повторное использование ID не возвращали награду. Удаление привычки убирает её пользовательскую историю; защищённые сведения об уже выплаченных днях остаются в документе владельца. Лимит всего сохранения по-прежнему 800 КБ; при достижении показывается существующая ошибка сохранения без сброса данных.

Дата привычки вычисляется в часовом поясе устройства на момент её создания, с фиксированным смещением UTC. Переключение часового пояса устройства не даёт вторую выплату. Автоматическая сезонная смена смещения пока не предусмотрена. Пропуск запланированного дня разрывает серию; выходной день её не разрывает.

Это защита правил персональных наград, а не полная серверная переработка старых механик XP, магазина и комнат. Владелец по-прежнему самостоятельно отмечает выполнение своих реальных целей.

## Проверка и выпуск

- `npm run check`
- `npm test`
- Firestore Emulator: `npx --yes --package firebase-tools@15.32.1 firebase emulators:exec --only firestore --project demo-play-your-life "node --experimental-strip-types --test tests/firebase-rules.test.mjs"`
- `npm run test:quests-ui` (после `npx playwright install chromium`; для системного Chromium — `LIFEGAME_CHROMIUM_PATH=/usr/bin/chromium npm run test:quests-ui`). Проверки браузера на 1440×1100 и 390×844: создание, фото-preview, лимиты, прогресс, блокировка награды, выполнение, инвентарь, привычка, поиск и перезагрузка.

**Перед выпуском обновить Security Rules существующего Firebase проекта:**

`firebase deploy --only firestore:rules --project play-your-life-872b1`

Затем выпустить проверенный коммит через существующий GitHub Pages workflow и перезагрузить открытые старые вкладки приложения. Нужен доступ владельца к публикации правил. Без новых правил обновлённые облачные сохранения будут отклоняться; поэтому публикация frontend до подтверждённого обновления Rules запрещена в этом выпуске. Проект и тариф не меняются.
