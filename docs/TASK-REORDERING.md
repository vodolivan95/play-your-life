# Ручная перестановка задач

Кандидат 0.83.3. Новых полей сохранения и новых внешних сервисов нет: порядок остаётся в существующем `state.quests` и восстанавливается вместе с обычным сохранением игры.

## Поведение

- В списке проекта и на экране задач этапа можно двигать задачу на любое место, в том числе сразу в конец; перестановка не ограничена одним соседним шагом.
- На сенсорном экране перетаскивание начинается с ручки `⋮⋮`, чтобы прокрутка списка в остальной части карточки оставалась обычной. Удержание ручки сразу выделяет карточку тонкой синей рамкой.
- На компьютере перетаскивание начинается удержанием основной кнопки мыши на любой части карточки; порог движения предотвращает случайный перенос при обычном клике. Карточка получает ту же синюю рамку.
- Список оставляет место в исходной позиции, показывает линию вставки и явную цель «В конец списка». Удержание у верхней/нижней кромки окна мягко прокручивает длинный список.
- Ручка доступна с клавиатуры: стрелки вверх/вниз меняют позицию, Home перемещает в начало, End — в конец. Перемещение сопровождается сообщением для screen reader.

## Где доступно

- Рабочее пространство проекта и список задач выбранного этапа — в порядке сохранённого списка.
- Экран этапа — только в режиме сортировки «По порядку», как и раньше; активный поиск, фильтр статуса и сортировки «Приоритет», «Срок» и «Название» не смешиваются с ручным порядком.
- «Мои задачи → Список» — отдельный режим «Вручную»; «Закреплённые сверху» сохраняется как обычная сортировка.
- «Задачи на сегодня» — режим «Вручную» рядом с сортировкой по времени.
- «Мой план» — режим «Вручную» в виде списка, канбана и матрицы. Канбан/матрица меняют порядок внутри текущего столбца; перетаскивание не меняет статус или дату задачи.

Календарь продолжает трактовать перетаскивание как изменение времени/срока, а не ручного порядка. Удалённые входящие TickTick остаются read-only до явного принятия в игру. Шкала сроков планировщика остаётся инструментом перемещения дат.

## Реализация и проверки

`reorderTaskList()` в `src/planning.ts` переставляет только ID текущего видимого списка в сохранённом массиве и сохраняет порядок остальных задач. `TaskReorderList.tsx` обрабатывает указатель, синюю рамку, drop target, клавиатурные команды и объявление позиции. Экран этапа использует его существующий обработчик stage-task order с теми же визуальными и сенсорными правилами.

Unit-тесты покрывают вставку после произвольной задачи, перенос в конец, перестановку выбранного подсписка и сохранение порядка других этапов/списков. Локально прошли `npm run check`, `npm test` (643/643), `LIFEGAME_CHROMIUM_PATH=/usr/bin/chromium npm run test:quests-ui` (desktop и mobile), `npm run test:goals-ui` (1440/768/390/360 px) и `LIFEGAME_CHROMIUM_PATH=/usr/bin/chromium node tests/planner-ui.mjs` (desktop/mobile). CI ветки запускается вместе с pull request.
