# Ручная перестановка задач

Кандидат 0.83.6. Новых полей сохранения и новых внешних сервисов нет: порядок остаётся в существующем `state.quests` и восстанавливается вместе с обычным сохранением игры.

## Поведение

- В списке проекта и на экране задач этапа можно двигать задачу на любое место, в том числе сразу в конец; перестановка не ограничена одним соседним шагом.
- Во вкладке проекта (все задачи проекта и задачи выбранного этапа) и на экране этапа на каждой карточке явно видна одинаковая ручка `⋮` слева: 44×44 px, контрастная голубая подложка и контур. Она достаточно заметна и на компьютере, и на телефоне; удержание ручки выделяет карточку синей рамкой.
- На сенсорном экране перетаскивание начинается с ручки, а прокрутка в остальной части карточки остаётся обычной.
- На компьютере перетаскивание начинается удержанием основной кнопки мыши на любой части карточки; порог движения предотвращает случайный перенос при обычном клике. Карточка получает ту же синюю рамку.
- Список оставляет место в исходной позиции, показывает линию вставки и явную цель «В конец списка». Удержание у верхней/нижней кромки окна мягко прокручивает длинный список.
- После изменения порядка карточки плавно занимают новые места по FLIP: координаты First снимаются непосредственно перед reorder, Last — после React layout, затем Web Animations API проигрывает инвертированное смещение обратно к нулю. Перестановка мышью, касанием или клавиатурой использует тот же эффект; при `prefers-reduced-motion: reduce` FLIP отключён.
- `IntersectionObserver` кэширует видимые карточки, поэтому First/Last layout reads не обходят весь длинный список. За один reorder анимируются максимум 8 ближайших видимых карточек на телефоне (190 мс) и 16 на desktop (280 мс). Скролл немедленно останавливает активные FLIP-эффекты, а новый reorder в течение 140 мс после последнего scroll-события пропускает движение карточек, чтобы не отнимать кадры у нативной/инерционной прокрутки.
- Ручка доступна с клавиатуры: стрелки вверх/вниз меняют позицию, Home перемещает в начало, End — в конец. Перемещение сопровождается сообщением для screen reader.

## Где доступно

- Рабочее пространство проекта и список задач выбранного этапа — в порядке сохранённого списка.
- Экран этапа — только в режиме сортировки «По порядку», как и раньше; активный поиск, фильтр статуса и сортировки «Приоритет», «Срок» и «Название» не смешиваются с ручным порядком.
- «Мои задачи → Список» — отдельный режим «Вручную»; «Закреплённые сверху» сохраняется как обычная сортировка.
- «Задачи на сегодня» — режим «Вручную» рядом с сортировкой по времени.
- «Мой план» — режим «Вручную» в виде списка, канбана и матрицы. Канбан/матрица меняют порядок внутри текущего столбца; перетаскивание не меняет статус или дату задачи.

Календарь продолжает трактовать перетаскивание как изменение времени/срока, а не ручного порядка. Удалённые входящие TickTick остаются read-only до явного принятия в игру. Шкала сроков планировщика остаётся инструментом перемещения дат.

## Реализация и проверки

`reorderTaskList()` в `src/planning.ts` переставляет только ID текущего видимого списка в сохранённом массиве и сохраняет порядок остальных задач. `TaskReorderList.tsx` обрабатывает указатель, синюю рамку, drop target, клавиатурные команды и объявление позиции. Переиспользуемый hook `useFlipAnimation.ts` кэширует видимые DOM-узлы через `IntersectionObserver`, снимает First и Last только для них, а `useLayoutEffect` запускает ограниченный набор FLIP после нового layout; scroll listener отменяет композиционные эффекты и snapshot. Экран этапа использует тот же hook рядом с собственным обработчиком stage-task order.

Для кандидата 0.83.6 UI-регрессия `npm run test:goals-ui` проверяет наличие контрастной ручки 44×44 px в workspace проекта и на экране этапа на ширинах 1440/768/390/360 px, включая реальный reorder, reload и сохранение порядка. Полный CI для коммита выполнит обязательные `npm run check` и `npm test`.
