# Подключение TickTick: что нажать

Для PLAY YOUR LIFE выбран прямой обмен через TickTick Open API. Код сервера и публикации уже находится в репозитории. В TickTick уходят конкретные задачи; цели и этапы остаются в PLAY YOUR LIFE. Задача здоровья попадает в сопоставленный список «Здоровье», задача английского — в «Английский язык».

## 1. Подготовить адрес сервера

Открой [Cloudflare](https://dash.cloudflare.com/), создай аккаунт или войди. Настрой поддомен Workers для своего аккаунта. Адрес будущего сервера составляется так:

`https://play-your-life-ticktick.ТВОЙ-ПОДДОМЕН.workers.dev`

Это пока адрес будущей публикации, а не подтверждение, что сервер запущен. Его можно прислать для проверки: он публичный, пароля в нём нет.

## 2. Зарегистрировать подключение в TickTick

Открой [TickTick Developer](https://developer.ticktick.com/manage), войди на сайте TickTick и создай приложение с названием **PLAY YOUR LIFE**. В поле **Redirect URI** укажи адрес будущего сервера с `/callback` в конце:

`https://play-your-life-ticktick.ТВОЙ-ПОДДОМЕН.workers.dev/callback`

Сохрани выданные **Client ID** и **Client Secret**. Это ключи подключения приложения, а не логин и пароль твоего аккаунта. Client Secret нельзя присылать в чат или вставлять в исходный код.

## 3. Добавить четыре секрета в GitHub

В Cloudflare скопируй **Account ID** и создай API token по шаблону **Edit Cloudflare Workers** для своего аккаунта.

Открой [секреты репозитория](https://github.com/vodolivan95/play-your-life/settings/secrets/actions). Нажимай **New repository secret** и добавь:

| Имя | Значение |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из Cloudflare |
| `CLOUDFLARE_API_TOKEN` | API token из Cloudflare |
| `TICKTICK_CLIENT_ID` | Client ID приложения TickTick |
| `TICKTICK_CLIENT_SECRET` | Client Secret приложения TickTick |

Все значения вводятся только в поля секретов GitHub. Пароль TickTick сюда не добавляется.

## 4. Опубликовать сервер

Открой [Deploy TickTick bridge](https://github.com/vodolivan95/play-your-life/actions/workflows/ticktick.yml). Нажми **Run workflow**, выбери **main** и ещё раз **Run workflow**. Дождись зелёной отметки. Адрес опубликованного Worker проверь в журнале шага **Deploy OAuth server** или в Cloudflare.

Необязательно: для автоматической публикации последующих изменений сервера добавь [переменную репозитория](https://github.com/vodolivan95/play-your-life/settings/variables/actions) `TICKTICK_ENABLED` со значением `true`.

## 5. Разрешить доступ к своему TickTick

Открой [PLAY YOUR LIFE](https://vodolivan95.github.io/play-your-life/). В личной игре перейди **Профиль → План жизни → TickTick**:

1. Вставь адрес опубликованного сервера.
2. Нажми **Подключить аккаунт**.
3. На сайте TickTick разреши чтение и изменение задач (`tasks:read tasks:write`).
4. После возвращения нажми **Проверить подключение**.
5. Проверь сопоставление сфер со списками: «Здоровье» → «Здоровье», «Английский» → «Английский язык» и остальные.

Сфера без выбранного списка не отправляет новые задачи. Авторизация аккаунта — обязательный шаг владельца; одного логина и пароля недостаточно для регистрации OAuth-приложения и публикации сервера.

## 6. Проверить на одной задаче

В цели создай конкретную задачу, например «Аудирование 1 час», с началом и сроком через час. В строке задачи нажми стрелку → **Отправить задачу в TickTick**.

Проверь, что в списке «Английский язык» появилась одна задача с правильным временем. Цель и этап не должны появиться отдельными задачами. Повтори синхронизацию: копии быть не должно. Выполни задачу в TickTick, затем нажми **Синхронизировать сейчас** в PLAY YOUR LIFE: задача должна завершиться и XP начислиться один раз.

Только после этой проверки подключение можно считать работающим с реальным аккаунтом. Автоматический обмен работает, пока PLAY YOUR LIFE открыто; настройка находится на экране подключения.

## Источники и пределы проверки

- [TickTick Developer: документация](https://developer.ticktick.com/docs#/openapi) — основной источник для регистрации приложения и Open API.
- [Открытый TickTick SDK](https://github.com/dev-mirzabicer/ticktick-sdk) — дополнительная сверка процедуры Client ID / Client Secret / Redirect URI и OAuth.
- [Подробное описание нашей интеграции](TICKTICK.md).

При подготовке этой инструкции официальные страницы TickTick, Zapier и IFTTT были недоступны из рабочего окружения. Открытый SDK доступен и прочитан; он сторонний и не заменяет официальную документацию. Возможности текущих интеграций Zapier и IFTTT не подтверждены. Опубликованный сервер и реальная авторизация аккаунта пока не проверены; автоматические тесты используют имитацию API.
