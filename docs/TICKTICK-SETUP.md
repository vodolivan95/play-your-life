# TickTick: однократная настройка сайта и подключение пользователей

Код подключения подготовлен в PLAY YOUR LIFE. Для живого обмена владелец сайта сначала регистрирует одно OAuth-приложение и публикует один сервер. После этого каждый пользователь входит в PLAY YOUR LIFE и подключает **свой** TickTick. Пользователю не нужны Client Secret, Cloudflare или отдельное приложение разработчика.

## Что уже работает в коде

- Вход и регистрация PLAY YOUR LIFE остаются существующими, через Firebase.
- **Профиль → Мой TickTick**: вход через сайт TickTick, подтверждение доступа загрузкой списков, девять сопоставлений, сохранение, ручной и автоматический обмен, отключение.
- Сервер проверяет подпись Firebase ID token, проект, сроки и UID. OAuth-токен TickTick хранится только на сервере, отдельно по UID.
- Сопоставления и связи задач доступны с другого устройства после входа в тот же аккаунт PLAY YOUR LIFE. Их устаревшая версия не может автоматически перезаписать более новую.
- Новое подключение не включает автоматическую отправку и удаление задач. Выбор списков нужно сохранить.

## Владелец сайта: сделать один раз

### 1. Получить адрес Cloudflare Worker

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/) и войдите в свой аккаунт.
2. Откройте **Workers & Pages**, настройте поддомен `workers.dev` для аккаунта, если он ещё не настроен.
3. Сервер из этого репозитория называется `play-your-life-ticktick`. Его будущий адрес:

   `https://play-your-life-ticktick.ВАШ-ПОДДОМЕН.workers.dev`

4. Скопируйте **Account ID** этого аккаунта.
5. В **My Profile → API Tokens → Create Token** выберите шаблон **Edit Cloudflare Workers** и ограничьте токен своим аккаунтом. Сохраните токен в защищённом месте. Он будет нужен только для публикации из GitHub.

Адрес выше — шаблон, а не опубликованный сервер. Не копируйте слово «ВАШ-ПОДДОМЕН» буквально.

### 2. Зарегистрировать OAuth-приложение TickTick

1. Откройте [TickTick Developer](https://developer.ticktick.com/manage) и войдите в свой аккаунт TickTick.
2. Создайте приложение **PLAY YOUR LIFE**.
3. В **Redirect URI** укажите **точный адрес Worker с `/callback`**:

   `https://play-your-life-ticktick.ВАШ-ПОДДОМЕН.workers.dev/callback`

4. Сохраните **Client ID** и **Client Secret**. Это ключи приложения, а не пароль пользователя TickTick.

Client Secret, Cloudflare API token и пароли нельзя присылать в чат, вставлять в React-код или в переменные `VITE_*`. Вход каждого пользователя позже происходит непосредственно на сайте TickTick, с правами `tasks:read tasks:write`.

### 3. Записать четыре секрета GitHub

1. Откройте [секреты репозитория](https://github.com/vodolivan95/play-your-life/settings/secrets/actions).
2. Нажимайте **New repository secret** и добавьте четыре записи:

| Имя | Значение |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID из шага 1 |
| `CLOUDFLARE_API_TOKEN` | API token из шага 1 |
| `TICKTICK_CLIENT_ID` | Client ID из шага 2 |
| `TICKTICK_CLIENT_SECRET` | Client Secret из шага 2 |

Значения вводятся только в поля секретов GitHub. Публичный проект Firebase уже указан в `integrations/ticktick/wrangler.toml`: `play-your-life-872b1`. Административный ключ Firebase этому серверу не нужен; правила Firestore менять не требуется.

### 4. Опубликовать сервер

1. Откройте [Actions → Deploy TickTick bridge](https://github.com/vodolivan95/play-your-life/actions/workflows/ticktick.yml).
2. Нажмите **Run workflow**, выберите **main** и запустите.
3. Дождитесь зелёной отметки. При сообщении о недостающем секрете вернитесь к шагу 3.
4. Проверьте фактический HTTPS-адрес Worker в шаге **Deploy OAuth server** или в Cloudflare. Убедитесь, что его `/callback` совпадает с Redirect URI в TickTick.

Workflow публикует код Worker и OAuth-секреты; задачи пользователей он не создаёт и не меняет. Если в Cloudflare отключена доступность Worker по `workers.dev`, включите её для этого Worker. Пересоздавать Firebase или удалять пользовательские данные не нужно.

### 5. Указать общий адрес для пользователей и обновить сайт

1. Откройте [переменные GitHub Actions](https://github.com/vodolivan95/play-your-life/settings/variables/actions).
2. Добавьте **Repository variable** `VITE_TICKTICK_BRIDGE_URL` со значением фактического адреса Worker, **без `/callback`, других путей и параметров**, например `https://play-your-life-ticktick.ВАШ-ПОДДОМЕН.workers.dev`.
3. Для автоматической публикации следующих изменений сервера добавьте переменную `TICKTICK_ENABLED` со значением `true`.
4. Откройте [Deploy to GitHub Pages](https://github.com/vodolivan95/play-your-life/actions/workflows/pages.yml), нажмите **Run workflow → main → Run workflow**. Изменение переменной само по себе не обновляет уже собранный сайт.
5. Дождитесь зелёной публикации. Откройте [PLAY YOUR LIFE](https://vodolivan95.github.io/play-your-life/), обновите страницу.

После этого в профиле будет готова кнопка подключения; обычным пользователям адрес сервера вводить не нужно. Пока общая переменная не указана, приложение показывает состояние «Подключение сайта ещё не настроено». Дополнительное поле адреса предусмотрено для проверки собственного сервера владельцем.

## Каждый пользователь: подключить свой аккаунт

1. Откройте PLAY YOUR LIFE. Нажмите **Вход** или **Регистрация**; используйте свою почту и пароль PLAY YOUR LIFE. Вход администратора Firebase к этому не относится.
2. Откройте **Профиль → Мой TickTick → Подключить TickTick**.
3. На сайте TickTick войдите **в нужный личный аккаунт** и разрешите доступ к задачам. Пароль TickTick не вводится в PLAY YOUR LIFE.
4. После возврата в профиль дождитесь статуса **Подключён**. Он появляется только после подтверждения доступа и загрузки ваших списков.
5. Для каждой сферы выберите собственный список: например, «Спорт» → «Мои тренировки», «Финансы» → «Личный бюджет». Можно выбрать **Не синхронизировать**. Списки заметок не показываются. Предложение совпадений по названиям не сохраняет настройки автоматически.
6. Нажмите **Сохранить настройки**. По умолчанию автоматический обмен и удаление выключены. Включайте их осознанно; несохранённые настройки приостанавливают обмен.
7. Для первого обмена нажмите **Синхронизировать сейчас**. Перед этим проверьте активные задачи целей: ручной общий обмен отправляет новые задачи целей в сопоставленные списки. Для проверки только одной задачи используйте её кнопку передачи внутри цели.

На другом телефоне или компьютере войдите **в тот же PLAY YOUR LIFE**. Настройки и связи загружаются с сервера; повторная OAuth-авторизация нужна только при отсутствии или истечении доступа. В другом аккаунте PLAY YOUR LIFE чужие настройки не видны.

## Проверка живого обмена на тестовых данных

Используйте отдельный тестовый аккаунт PLAY YOUR LIFE и отдельный тестовый аккаунт/список TickTick. Не проверяйте запись на реальных рабочих задачах.

1. Создайте тестовую цель и одну задачу со сроком. Сопоставьте её сферу с тестовым списком.
2. Отправьте эту задачу из цели. Убедитесь, что в TickTick появилась одна задача с правильным названием и датами.
3. Повторите обмен: второй копии быть не должно.
4. Выполните задачу в TickTick и обновите PLAY YOUR LIFE. Задача завершается, прогресс обновляется, награда начисляется один раз.
5. Перезагрузите PLAY YOUR LIFE и повторите обмен: XP и монеты не должны начислиться повторно.
6. Войдите с другого устройства: сопоставления и связи доступны тому же пользователю.
7. Нажмите **Отключить TickTick**. Серверный доступ и настройки подключения очищаются; задачи и прогресс остаются в обоих приложениях. Для отзыва разрешения у провайдера удалите приложение в настройках подключений TickTick.

Передаются конкретные задачи целей, их текст, даты, приоритет и выполнение. Самостоятельные квесты, привычки и посторонние задачи TickTick не импортируются. Смена списка применяется к новым задачам; ранее связанные остаются в исходном списке. Повторная OAuth-авторизация сбрасывает сопоставления и связи, чтобы случайно не использовать идентификаторы другого TickTick.

Если настройки изменены на другом устройстве, автоматическая перезапись останавливается. Нажмите **Обновить подключение**, затем проверьте выбор и сохраните. При отсутствии сети игра использует прежнее сохранение; при включённом автоматическом обмене повторная отправка происходит после восстановления сети, пока приложение открыто. Фонового обмена при закрытом сайте нет.

Общий адрес сервера сам по себе не блокирует восстановление игровой резервной копии. Блокировка действует для действительно подключённого либо ранее подтверждённого подключения, в том числе офлайн, чтобы импортированный план не отправился автоматически. После отключения TickTick восстановление снова доступно. Если приложение загрузилось при недоступном сервере, после возврата сети оно повторно проверяет доступ и загружает настройки аккаунта.

## Что подтверждено и что ещё не подтверждено

Проверки с имитацией сервисов подтверждают OAuth/state, подпись Firebase JWT, изоляцию UID, девять сопоставлений, сохранение на разных устройствах, конфликты, отсутствие дублей, однократные награды, офлайн и мобильный интерфейс. Реальные аккаунты при разработке не затрагиваются.

9 октября 2026 владелец сообщил, что приложение TickTick и сервер ещё не настроены. Их регистрация, публикация и реальная авторизация пока не подтверждены. Сетевой доступ рабочего окружения к TickTick/Cloudflare также не подтверждён. Успешная публикация Pages или тесты не заменяют живую проверку после выполнения этой инструкции.

Официальная документация: [TickTick Open API](https://developer.ticktick.com/docs#/openapi), [Firebase ID token verification](https://firebase.google.com/docs/auth/admin/verify-id-tokens). Архитектура проекта: [TICKTICK.md](TICKTICK.md).
