# 03 — Отчёт об ошибках

Версия: 0.75.1. Приоритеты по методологии ТЗ: P0 критические / P1 высокие / P2 средние / P3 дополнительные.

Этот отчёт разделяет три категории, как требует ТЗ (раздел 27): **подтверждённые проблемы** (воспроизведены по коду или логу CI), **вероятные риски** (найдены по анализу, не воспроизведены построчным тестом) и **уже исправленные** (историческая запись — не считать открытыми).

## Подтверждённые открытые проблемы

### P2 — CI: нестабильный скриншот-тест 3D-комнаты «Спорт»

- **Где:** workflow «Verify coastal city and 3D rooms», шаг `health-room-smoke.mjs`/аналогичный скрипт для комнаты «Спорт».
- **Подтверждение:** прогон CI на main от 8 ноября 2026 (run `42495125100`, коммит `bf99f58`/merge PR #294): `page.screenshot: Timeout 30000ms exceeded` — ожидание шрифтов и затем таймаут самого скриншота.
- **Влияние:** этот workflow **не входит** в обязательный `Project checks` (тот прошёл успешно на том же коммите) — на публикацию и слияние PR это не повлияло, но означает, что 3D-визуальные регрессии в комнатах сфер сейчас не контролируются надёжно.
- **Рекомендация:** увеличить таймаут скриншота или дождаться загрузки шрифтов отдельным `waitForLoadState`/ретраем; либо сделать шаг не блокирующим с явной пометкой.

### P2 — README.md не синхронизирован с версией

- **Где:** `README.md`, строка с «Текущая версия приложения — 0.64.6».
- **Подтверждение:** `package.json` → `0.75.1`; разница — 11 релизов.
- **Влияние:** вводит в заблуждение внешнего читателя репозитория (не влияет на работу приложения).
- **Рекомендация:** автоматизировать подстановку версии в README тем же скриптом, что обновляет `index.html`/`package.json` (уже упомянут в `AGENTS.md` как обязательный шаг релиза — видимо, пропущен в недавних релизах).

### P3 — TODO.md расходится с фактически реализованным

- **Где:** `TODO.md` (датирован 23 октября) содержит невыполненные `[ ]` пункты по редизайну главной страницы; часть из них по смыслу уже покрыта `HomeYearSummary.tsx`, но файл не обновлён.
- **Влияние:** риск дублирования работы или путаницы у следующего исполнителя (Codex/ChatGPT), который доверится TODO.md как актуальному бэклогу.
- **Рекомендация:** свериться с Иваном, что из TODO.md выполнено, и обновить/закрыть файл.

## Вероятные риски (не воспроизведены построчно, требуют точечной проверки)

### P1 — AUD-007: нет серверного потолка роста XP

- **Источник:** `docs/AUDIT-2026-10-29.md`, открытый пункт на момент публикации; по `firestore.rules` на 0.75.1 найдена проверка XP **за одно событие** (`questXpOk`, фиксированные значения 5/10/20/35/40/50/80), но не найдено ограничение **суммарного** роста XP за период — то есть монеты защищены лимитом, XP — нет, как и было отмечено в октябрьском аудите.
- **Риск:** при обнаружении клиентского способа отправить много легитимных по форме, но аномально частых событий, статистика/рейтинг XP можно накрутить. Сегодня рейтингов между игроками нет (раздел 13 ТЗ подтверждает только «рейтинг игроков» как идею), поэтому практический ущерб низкий, но это системный пробел, который станет критичным при добавлении мультиплеера/рейтингов.
- **Рекомендация:** см. `docs/AUDIT-2026-10-29.md` — не вводить простой лимит (экономика разнообразна), а сделать журнал всех начислений с типом события, если появятся рейтинги.

### P2 — AUD-008: уязвимости в dev-зависимостях npm audit

- **Источник:** `docs/AUDIT-2026-10-29.md` на 0.64.6: `npm audit --omit=dev` = 0 уязвимостей; полный audit (включая dev) = 12 moderate, затронуты только ESLint/minimatch и их lint-зависимости. Статус на 0.75.1 **не переподтверждён** в рамках этого аудита (решено не гонять `npm audit`/`npm ci` локально — см. 09-TEST_RESULTS.md и предпочтение пользователя проверять через CI).
- **Риск:** низкий — только build-time/lint-tooling, не попадает в production-бандл.
- **Рекомендация:** проверить в ближайшем CI-прогоне `npm audit --omit=dev`; обновить ESLint-цепочку при следующем плановом апдейте зависимостей.

### P3 — AUD-009: CSS-бюджет близок к лимиту

- **Источник:** `docs/planning-system-2.0/AUDIT.md`, прогон на 0.73.x: CSS **86.5/87 КБ** gzip (99% лимита), главный JS 452.3/460 КБ. На 0.75.1 размеры не переизмерялись в рамках этого аудита.
- **Риск:** следующий же UI-патч с новыми стилями (например, доработка канбана «Мой план» под drag-and-drop) рискует пробить бюджет и уронить `check:budgets` в CI.
- **Рекомендация:** либо поднять лимит `scripts/check-budgets.mjs` заранее с объяснением, либо почистить неиспользуемые стили перед следующим визуальным изменением.

### P2 — два параллельных механизма приоритизации задач

- **Источник:** анализ модели данных, `02-FUNCTIONAL_AUDIT.md`: `Quest.priority: 'low'|'normal'|'high'` (синхронизируется с TickTick) и отдельно `TaskPlanning.important`/`urgent` (используются только в матрице Эйзенхауэра «Мой план»).
- **Риск:** не ошибка в строгом смысле, но архитектурный риск путаницы — пользователь может выставить «high» приоритет в одном месте и не увидеть эффекта в матрице важно/срочно, которая смотрит на другие два булевых поля.
- **Рекомендация:** на этапе 2 дорожной карты решить, объединять ли эти два механизма или явно развести их по смыслу в интерфейсе (с подсказкой).

### P3 — удаление задачи без восстановления

- **Источник:** анализ кода (раздел 5, `02-FUNCTIONAL_AUDIT.md`) — не найден механизм «корзины»/восстановления удалённой задачи, в отличие от обратимой отметки `wontDo`.
- **Риск:** случайное безвозвратное удаление данных пользователя.
- **Рекомендация:** либо подтвердить диалогом с явным предупреждением (возможно, уже есть — не проверено на UI), либо ввести мягкое удаление (`deletedAt`) по аналогии с `archivedAt`.
