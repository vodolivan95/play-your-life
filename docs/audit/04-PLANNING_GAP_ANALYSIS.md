# 04 — Анализ пробелов для полноценного планировщика

Версия: 0.75.1. База: инвентаризация `docs/planning-system-2.0/AUDIT.md` (7 ноября, на 0.73.2) и `docs/planning-system-2.0/IMPLEMENTATION.md`, обновлено по факту появления «Мой план» (0.74.0–0.75.1) и зависимостей задач (0.75.0). Цель раздела — ответить на главный вопрос ТЗ: чего не хватает, чтобы PLAY YOUR LIFE стал полноценным приложением личного планирования, **не предлагая повторную разработку уже готового**.

## Уже закрыто Planning System 2.0 (не включать в новый бэклог)

- Локальные входящие без TickTick (`planning.inbox`), явный признак разбора.
- Канбан-доска по статусам `planned/ready/doing/waiting/done` (`PlanningWorkspace.tsx`).
- Матрица важно/срочно (Эйзенхауэра).
- Шкала сроков задач/этапов с ручным переносом.
- Зависимости задач с проверкой циклов и блокировкой старта/выполнения (`taskDependencies.ts`, 0.75.0).
- Настройки доступных минут/дней/резерва/лимитов (`PlanningSettings`).
- Дневной фокус (`mainLimit`), порог предупреждения о переносах (`moveWarning`), WIP-лимит (`wipLimit`).
- «Этапы в работе» — только незавершённые доступные этапы с собственными датами (0.75.1, Issue #293).

Это значит, что часть пунктов раздела 18 ТЗ («Поиск недостающего функционала») — Inbox, базовый канбан, зависимости — формально **уже реализована**, и заказ их заново был бы повторной разработкой, прямо запрещённой ТЗ (раздел 25: «Не предлагай повторную разработку того, что уже работает»).

## Действительно отсутствующее (по областям ТЗ, раздел 18)

### Планирование

| Функция | Статус | Комментарий |
|---|---|---|
| Inbox | Есть | локальный, без TickTick |
| Сегодня | Есть | `TodayTasks.tsx` |
| Завтра | Требует проверки | отдельной вкладки «Завтра» не найдено — вероятно, покрывается календарём/списком с фильтром даты |
| Неделя | Есть | `TasksCalendar` неделя/2 недели |
| Месяц | Есть | `TasksCalendar` месяц + `LifePlanMap` |
| Квартал | **Нет** | ни отдельного вида, ни агрегации по кварталу не найдено |
| Год | Частично | есть годовой *отчёт* (`yearReport.ts`), нет годового *планирования вперёд* (постановка целей на год как отдельного вида) |
| Планирование по времени (time blocking) | Частично | интервалы задач есть, отдельная сущность «временной блок» и проверка пересечений — не подтверждены |
| Главные задачи дня | Есть | `mainLimit`/дневной фокус |
| Недельные результаты | Частично | `weeklyFocus`/`weeklyFocusGoal` на уровне проекта есть; агрегированного «итога недели» по всем проектам/сферам сразу — не найдено (мастер подтверждения недели прямо зафиксирован как отсутствующий) |

### Управление задачами

| Функция | Статус |
|---|---|
| Подзадачи | Есть |
| Приоритеты | Есть, но раздвоены на два механизма (см. 03-BUG_REPORT.md) |
| Зависимости | Есть (0.75.0), без автоматического каскадного переноса сроков — осознанное решение (`AGENTS.md`: «Сроки зависимых задач сами не меняются») |
| Повторения | Есть базовые (daily/weekdays/weekly/monthly); **нет**: «каждые N дней», выбор конкретных дней месяца, «ежегодно», явного конца серии, пропусков с сохранением серии, раздельного изменения будущих экземпляров |
| Массовые операции | **Нет** |
| Сохранённые фильтры | **Нет** |
| История переносов | **Нет** как структурированный журнал (есть общий событийный лог) |

### Проекты

| Функция | Статус |
|---|---|
| Канбан (на уровне проекта/задач проекта) | Частично — общий канбан «Мой план» существует, но не отфильтрован именно под один проект отдельным видом |
| Гант | **Нет** — есть только полосы этапов (`LifePlanMap`) и шкала сроков задач, не полноценная Gantt-диаграмма с зависимостями между этапами |
| Контроль следующего действия | Есть | `goalWorkspace.ts` — «следующий шаг» |
| Контроль неактивных проектов | Частично | есть «темп» (pace) проекта, явного флага «застрял/неактивен N дней» не найдено |
| Управление дедлайнами | Есть | даты этапов/проекта |

### Аналитика

| Функция | Статус |
|---|---|
| Точность планирования (Plan Accuracy) | Требует проверки — нет подтверждённой отдельной метрики с таким названием |
| Фактическая нагрузка | **Нет** — зависит от отсутствующего учёта фактического времени |
| Выполнение плана | Частично — есть `daySummary`/`weekLoad`, не формализовано как единый % |
| Переносы (аналитика) | **Нет** — зависит от отсутствующей истории переносов |
| Прогресс проектов | Есть | `goalStatistics.ts`, темп, прогресс этапов |

### Интеллектуальные функции

| Функция | Статус |
|---|---|
| Проверка нагрузки | Частично | `weekLoad`, `dailyMinutes`/`reservePercent` в настройках — заготовка есть, полноценных рекомендаций («у тебя перегружен вторник») не подтверждено |
| Поиск свободного времени | **Нет** |
| Рекомендации по приоритетам | **Нет** |
| Анализ причин переносов | **Нет** (нет данных-источника — история переносов) |
| Предложения по распределению задач | **Нет** |
| Выявление остановившихся проектов | Частично | см. «контроль неактивных проектов» выше |

## Итоговый список недостающих возможностей для полноценного планировщика

Отсортировано по влиянию на основную цель ТЗ (не на техническую сложность — она в `08-DEVELOPMENT_ROADMAP.md`):

1. Учёт фактического времени выполнения задачи (факт vs план) + коэффициент точности оценки.
2. Структурированная история переносов (исходная дата, новая дата, причина, счётчик).
3. Квартальное и годовое планирование вперёд (не только отчёт по факту).
4. Расширенная модель повторений (N дней, конкретные дни месяца, ежегодно, конец серии, пропуски).
5. Массовые операции над задачами (мульти-выбор → перенести/удалить/сменить сферу).
6. Сохранённые пользовательские фильтры и представления.
7. Drag-and-drop в канбане «Мой план» (сейчас — выпадающий список).
8. Полноценный Гант с зависимостями этапов (не только задач) и визуализацией критического пути.
9. Проверка пересечений временных блоков в календаре + явная сущность «временной блок» отдельно от задачи.
10. Контроль неактивных проектов («застрял N дней без движения»).
11. Разделение или явное объединение двух механизмов приоритета (`priority` vs `important`/`urgent`).
12. Поиск свободного времени / рекомендации по распределению нагрузки.
13. Напоминания (push/локальные) для задач и привычек.
14. Массовая/единая система уведомлений (центр уведомлений с типами, тихими часами) — сейчас только счётчик в колокольчике.
15. Привязка привычки к цели/проекту.
16. Восстановление удалённой задачи (мягкое удаление).

Эти 16 пунктов — основа для `08-DEVELOPMENT_ROADMAP.md` (этапы 2–6) и верхних строк `03-BUG_REPORT.md`/нового функционала в финальном резюме чата.
