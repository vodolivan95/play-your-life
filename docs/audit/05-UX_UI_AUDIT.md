# 05 — UX/UI аудит

Версия: 0.75.1. **Метод и ограничение:** этот аудит выполнен статическим анализом кода и документации, без нового живого клика по production-сайту в браузере (не проводился интерактивный просмотр в рамках текущего прохода — только источники: код компонентов, `TODO.md` — собственные замечания Ивана от 23.10, и прошлый UI-smoke 29–31.10, который подтвердил, что все разделы открываются на desktop/mobile без ошибок и без горизонтального переполнения). Визуальные/субъективные пункты, которые требуют именно взгляда на экран, помечены «Требует проверки» и вынесены в вопросы владельцу (10-EXECUTIVE_SUMMARY.md). Требование ТЗ — не предлагать замену дизайна — соблюдено: все рекомендации ниже точечные.

## Требует проверки в живом UI (нельзя подтвердить статическим чтением кода)

1. Количество действий для создания задачи «на практике» (заявлено быстрым — 1 клик до формы, но реальное число полей для обязательного заполнения до сохранения не замерено).
2. Единообразие карточек/кнопок между недавно обновлёнными разделами («Проекты» 0.71.0–0.72.1, «Мой план» 0.74.0) и более старыми («Привычки», «Магазин») — редизайны шли по разделам отдельными итерациями, визуальная консистентность между ними не сверялась построчно.
3. Пустые состояния и состояния загрузки — есть `ErrorBoundary.tsx`, но покрытие именно *пустых* состояний (нет задач/целей/привычек) по каждому разделу не инспектировалось.
4. Мобильная адаптация полей новой «Матрицы Эйзенхауэра»/канбана (4 колонки на узком экране — обычно требует горизонтального скролла или сворачивания в список).
5. Доступность (контраст, размер тач-таргетов) — не оценивалась инструментально.

## Что сохранить без изменений (по прямому требованию ТЗ — не предлагать замену дизайна)

- Светлый игровой стиль, геймификационная эстетика сфер/города — согласно явному пожеланию в ТЗ и уже устоявшемуся бренду (`docs/BRAND.md`, эмблема «корона с горами»).
- Единая тема светлая/тёмная (0.14.0) — работает, менять не требуется.
- Структура меню в целом — доработки точечные (см. рекомендованную структуру в 10-EXECUTIVE_SUMMARY.md), не полная перестройка.

## Вывод

Серьёзных UX-катастроф в коде не обнаружено — структура разделов логична, навигация единообразна (`AppSidebar`/`MobileNav`), быстрый ввод задачи есть. Главная проблема — организационная, а не дизайнерская: главная страница перегружена дублирующими блоками (признано самим владельцем в TODO.md), и часть из этого уже могла быть устранена в последних версиях без обновления бэклога. **Рекомендуется перед этапом 2 дорожной карты провести один живой проход по сайту с Иваном** (10–15 минут), чтобы закрыть пункты «Требует проверки» выше и свериться, какие строки TODO.md уже выполнены.
