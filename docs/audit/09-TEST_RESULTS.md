# 09 — Результаты тестов

## Правило проверки, применённое в этом аудите

По явному постоянному правилу Ивана («не гонять локальные прогоны тестов и сборок — проверять только через CI, причина: локальные прогоны быстро съедают недельные лимиты»), в рамках этого этапа **не выполнялись** `npm ci`, `npm run check`, `npm test`, `npm run check:budgets` локально. Вместо этого использованы:

1. Результаты последнего прогона `Project checks` на самом `main` (GitHub Actions, коммит `bf99f58`, PR #294, 8 ноября 2026) — **успешно**, то есть на текущей опубликованной версии 0.75.1 lint, typecheck и сборка проходят.
2. Исторические прогоны unit/UI-тестов из `docs/AUDIT-2026-10-29.md` (469/469, 0.64.6) и `docs/planning-system-2.0/AUDIT.md` (502/502, 0.73.2+) как подтверждённая база — на момент этих прогонов всё было зелёным.
3. Итоги созданного этим аудитом PR (ветка `claude/audit-stage1-report`, только добавление документации в `docs/audit/`) будут видны во вкладке Actions репозитория после публикации — функциональный код не менялся, поэтому ожидается тот же зелёный результат, что и на `main`.

**Пояснение по сценарию E:** ТЗ просит проверить работоспособность истории переносов — по факту такой истории в продукте нет, поэтому сценарий невозможно «пройти успешно»; это зафиксировано как функциональный пробел (п.2 в сводном списке `04-PLANNING_GAP_ANALYSIS.md`), а не как ошибка теста.

**Не использовался рабочий пользовательский аккаунт для разрушительных тестов** — требование ТЗ соблюдено: ни один сценарий не выполнялся на реальных данных Ивана.

## Вывод

Код проходит все автоматические проверки на `main` (`Project checks` зелёный на 0.75.1). Единственный известный красный сигнал CI — необязательный визуальный regression для 3D-комнат. Живые пользовательские сценарии (A–D, F–H) технически правдоподобны по коду и ранее подтверждались смоук-тестами на более старых версиях, но не были заново пройдены вживую в рамках этого конкретного прохода аудита — честно помечены как непроверенные, а не как «работает», в соответствии с прямым требованием ТЗ («не объявлять тест пройденным без его выполнения»).
