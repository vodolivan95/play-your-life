PLAY YOUR LIFE — ЭТАП 3

Система исполнения задач, недельного контроля и завершения проектов

Техническое задание для Claude Code

Проект: PLAY YOUR LIFE
Базовая версия: 0.76.0, после публикации PR #296
Цель: помочь пользователю выполнять запланированные задачи, сократить систематические переносы и обеспечить стабильное продвижение проектов.

Статус: проект ТЗ. Не приступать к реализации до отдельного поручения.

---

1. Основная концепция

В PLAY YOUR LIFE уже реализованы управление задачами, проекты, этапы, привычки, игровые механики и аналитика.

В версии 0.76.0 добавлены история переносов, счётчики, фактическое время и показатели точности планирования.

Теперь необходимо использовать существующие данные для решения практических задач:

- Понимать, что нужно выполнить сегодня.
- Видеть задачи, которые постоянно откладываются.
- Контролировать продвижение к целям.
- Определять проекты без активности.
- Анализировать выполнение недельных планов.
- Сокращать количество незавершённых дел.
- Создавать удобные условия для концентрации.

Важно: TickTick остаётся основным инструментом создания задач и управления их расписанием.

PLAY YOUR LIFE не должен дублировать функциональность TickTick без существенной пользы.

2. Модуль «Контроль выполнения»

В существующем разделе «Мой план» добавить компактную систему контроля исполнения.

2.1. Основные показатели

Показывать:

- Всего активных задач.
- Запланировано на сегодня.
- Выполнено сегодня.
- Просрочено.
- Часто переносится.
- Заблокировано зависимостями.
- Не имеет плановой даты.
- Относится к активным проектам.

Использовать реальные данные из существующего GameState и TickTick.

Не создавать новые страницы для показателей, которые можно разместить в существующем разделе.

2.2. Быстрые фильтры

Добавить или улучшить:

- Требуют внимания.
- Часто переношу.
- Просроченные.
- Без даты.
- Связанные с проектами.
- Заблокированные.
- Все активные задачи.

Фильтр «Часто переношу» должен иметь возможность показывать задачи за всё время, независимо от выбранной даты календаря.

Текущие фильтры и сортировки сохранить.

3. Модуль «Застрявшие задачи»

Разработать механизм выявления задач, которые длительное время не продвигаются.

Учитывать:

- Количество переносов.
- Текущий статус.
- Плановую дату.
- Последнюю известную активность.
- Просрочку.
- Зависимости.
- Принадлежность к проекту.

Не считать отсутствие новых записей в PLAY YOUR LIFE доказательством того, что пользователь совсем не работал над задачей.

3.1. Категории

- Часто переносится.
- Просрочена.
- Ожидает другую задачу.
- Долго без подтверждённой активности.
- Требует уточнения плана.

3.2. Действия

Для каждой проблемной задачи предусмотреть:

- Открыть.
- Перейти в TickTick.
- Добавить подзадачу, если поддерживается.
- Просмотреть зависимости.
- Отметить как требующую пересмотра.
- Связать с целью или этапом.

Не переносить задачи автоматически.

4. Модуль «Контроль проектов»

Использовать существующую модель проектов и этапов.

Добавить показатели:

- Последняя подтверждённая активность.
- Количество открытых задач.
- Количество выполненных задач.
- Количество просроченных задач.
- Количество подтверждённых переносов.
- Ближайший срок.
- Следующий доступный шаг.
- Дни без зафиксированного продвижения.

4.1. Статусы проектов

Предусмотреть вычисляемые состояния:

- Продвигается.
- Требует внимания.
- Нет доступного следующего шага.
- Есть просроченные этапы.
- Нет подтверждённой активности.

Не создавать дополнительный ручной статус, если его можно достоверно вычислить по существующим данным.

4.2. Следующее действие

Для активного проекта отображать конкретную следующую задачу, если её можно определить.

Если задача заблокирована зависимостями, объяснять причину.

Если следующего действия нет, предложить назначить его.

5. Мастер недельного обзора

Создать удобный инструмент подведения итогов недели.

Он должен помогать оценивать исполнение планов и выбирать направления работы на следующую неделю.

5.1. Шаги мастера

Шаг 1. Итоги недели

- Выполненные задачи.
- Невыполненные задачи.
- Переносы.
- Просроченные задачи.
- Учтённое фактическое время.

Шаг 2. Проблемные задачи

Показывать наиболее часто переносимые и просроченные задачи.

Предлагать открыть их для пересмотра.

Шаг 3. Продвижение проектов

Показывать:

- Какие проекты продвинулись.
- Какие остались без подтверждённой активности.
- Какие этапы выполнены.
- Что требует внимания.

Шаг 4. Фокус следующей недели

Предлагать выбрать до трёх приоритетных проектов или направлений.

Выбор фокуса должен сохраняться в PLAY YOUR LIFE и не требовать автоматического изменения расписания TickTick.

Шаг 5. Подтверждение итогов

Сохранять недельный обзор с датой и ключевыми результатами.

Пользователь должен иметь возможность открыть предыдущие обзоры.

5.2. Требования

Мастер должен быть компактным, доступным с телефона и не требовать обязательного заполнения большого количества полей.

Сохранять только полезные данные, которые можно использовать в последующей аналитике.

6. Режим «Фокус»

Добавить в карточку задачи возможность открыть отдельный режим концентрации.

Показывать:

- Название задачи.
- Связанный проект.
- Плановую длительность.
- Учтённое время.
- Таймер.
- Основное действие для завершения задачи.
- Возможность перейти в TickTick.

Убрать из этого режима второстепенные игровые показатели.

Не изменять основную структуру приложения.

Использовать существующий механизм таймера.

Не создавать второй независимый учёт времени.

7. Аналитика эффективности

Использовать данные Этапа 2.

Добавить графики и показатели:

- Динамика переносов по неделям.
- Выполнение задач по дням.
- Динамика просроченных задач.
- Плановое и фактическое время.
- Доля задач с повторными переносами.
- Продвижение активных проектов.
- Распределение активности по сферам жизни.

7.1. Условия достоверности

Все показатели должны рассчитываться по фактическим данным.

Разделять:

- Данные TickTick.
- Данные PLAY YOUR LIFE.
- Подтверждённые события.
- Неоднозначные события.
- Отсутствующие значения.

При недостаточном количестве данных показывать соответствующее уведомление.

Не формировать фиктивные графики.

8. Контроль качества синхронизации TickTick

Развить существующий статус синхронизации.

Предусмотреть:

- Последнюю успешную синхронизацию.
- Последнюю неуспешную попытку.
- Статус подключения.
- Состояние ожидания.
- Предупреждение об устаревших данных.
- Ручной повтор синхронизации.

Сохранять необходимые временные метки между перезагрузками приложения.

Не создавать новый сервис синхронизации.

9. Улучшение канбана

Добавить drag-and-drop для существующего канбана Planning System 2.0.

Пользователь должен иметь возможность перетаскивать задачи между существующими рабочими статусами.

Требования:

- Использовать существующий "setTaskWorkflow".
- Сохранять изменения.
- Проверять права владельца.
- Учитывать зависимости задач.
- Поддерживать мобильные устройства.
- Оставить альтернативу управления через выпадающий список.
- Не менять игровые награды при простом перемещении между колонками.

Не добавлять новые статусы без обоснованной необходимости.

10. UX/UI

Сохранить существующую концепцию PLAY YOUR LIFE.

Требования:

- Светлый чистый интерфейс.
- Компактные карточки.
- Минимум лишних панелей.
- Единые отступы.
- Удобная мобильная адаптация.
- Понятная навигация.
- Никаких декоративных графиков без данных.
- Существующий игровой город не переделывать.

Для новых функций максимально использовать существующие компоненты и стили.

11. Архитектура и тестирование

Перед разработкой изучить актуальный код после Этапа 2 и определить, какие функции уже реализованы.

Не создавать дублирующие сущности.

Обязательно проверить:

- Сохранность данных.
- Синхронизацию Firebase.
- Совместимость TickTick.
- Работу старых сохранений.
- Связи задач с проектами.
- Повторяющиеся задачи.
- Учёт переносов.
- Учёт времени.
- Начисление XP и монет.
- Мобильную версию.

Добавить unit- и UI-тесты для новых сценариев.

Основные проверки выполнять через GitHub Actions согласно правилам репозитория.

12. Порядок разработки

Разделить Этап 3 на небольшие самостоятельные части.

3.1. Контроль выполнения и фильтры.

3.2. Контроль застрявших задач и проектов.

3.3. Недельный обзор.

3.4. Режим фокуса.

3.5. Аналитика исполнения.

3.6. Улучшение синхронизации TickTick.

3.7. Drag-and-drop канбана.

Для каждого блока определить зависимости и тестовые сценарии.

Не пытаться выполнить весь этап одним большим изменением, если это увеличивает риск регрессий.

13. Результат

После реализации пользователь должен:

- Видеть проблемные задачи.
- Понимать, какие дела постоянно переносит.
- Находить проекты без продвижения.
- Получать недельную сводку.
- Выбирать основные направления следующей недели.
- Работать над задачей в режиме концентрации.
- Видеть реальные показатели выполнения.
- Понимать актуальность данных TickTick.
- Пользоваться улучшенным канбаном.

Новые функции должны помогать доводить проекты и задачи до завершения.

Этап 3 начинать только после отдельного согласования. Не изменять код в рамках обсуждения этого ТЗ.
